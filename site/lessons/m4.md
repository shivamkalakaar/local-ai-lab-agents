## Learning objective
- Learn how the RAG pipeline is built and where it breaks, what to index, and how to search it.

## Why retrieval?
| LLM alone | LLM + retrieval |
|---|---|
| "What is the liability cap in msa_20?" | Retrieved: msa_20, 7.1: "...shall not exceed the fees paid by Customer in the thirty-six (36) months preceding the claim." |
| "Caps are usually 12 months of fees." (a guess) | "36 months of fees. Source: msa_20#7." Over our 12-month rule: flag it. |

- Don't ask the model to memorize everything. Give it the right text just in time.
- Dynamic: easy to add or update documents.
- Interpretable: the model can point to its source, so a person can check it.

## The RAG pipeline
- RAG: retrieval-augmented generation. Search first, then answer from what you found.
- Retriever: finds the top-k passages for a question.
- Generator: the LLM writes the answer from the question plus those passages.

```
question → search → top chunks → LLM answers → code checks the quote
```

## Do you even need it?
- Under about 200K tokens of documents: put everything in the prompt. Skip RAG.
- Above that: build the pipeline.
- Small local models do worse with long prompts, so RAG helps them sooner.

## Chunking: basic unit in retrieval
- Chunk: one piece of a document. Search returns chunks, not whole files.
- Fixed-size (e.g., 100–500 tokens)
  - Too small: the chunk has no context
  - Too large: one chunk mixes many topics
- Overlap: 10–20%, so no sentence is lost at a boundary.
- Structure: split on headings. For contracts, one section = one chunk.

## Why contextual retrieval
| Chunk | Contextualized chunk |
|---|---|
| "Each party's total liability ... shall not exceed the fees paid ... in the thirty-six (36) months preceding the claim." | "From msa_20, section 7 (Limitation of Liability). Each party's total liability ... shall not exceed the fees paid ... in the thirty-six (36) months ..." |

- The clause alone never says which contract it is from.
- Add a one-line label to each chunk before indexing (idea from Anthropic).

## Two ways to search
| Keyword search (BM25) | Meaning search (embeddings) |
|---|---|
| Scores chunks by shared words | Turns text into numbers; similar meaning → similar numbers |
| Finds "7.2(b)", "msa_15" | Finds "limitation of liability" when you typed "cap on damages" |
| Misses synonyms | Misses exact IDs and clause numbers |

- Hybrid retrieval: run both, then merge. Each catches what the other misses.

## Merging and reranking
- RRF (reciprocal rank fusion): merge two ranked lists.
  - Each chunk gets 1 / (60 + its rank) from each list. Add up, sort.
- Rerank (optional): fetch a wide pool, then a slower, more accurate model reorders it and keeps the best few.

## Scoring a retriever
- recall@k (also called Hit@k): how often the right chunk is in the top k.
- Measure retrieval on its own, before the answers.
  - If the final answer is wrong, you can't tell which part failed.
- Test with questions in different words from the contract: "how do we stop it renewing?"

## Checking citations in code
```python
hits = index.search(question, k=k)
ctx = "\n\n".join(f"[{c['id']}] {c['text']}" for c in hits)
a = structured([... "Answer only from the sources. Give the source id and an exact quote." ...], Answer)
src = next((c for c in hits if c["id"] == cid), None)
a_ok = src is not None and quote_is_in_doc(a.quote, src["text"])
```
- Line 1: hybrid search, keep the top k chunks.
- Line 2: join them, each tagged with its id, e.g. `[msa_20#7]`.
- Line 3: ask for an answer, a source id and an exact quote.
- Lines 4–5: find that chunk; check the quote is really in it.

## How this applies to us
- A firm has too many contracts to fit in one prompt. RAG sends only the clauses that matter.
- Search, embeddings and the LLM all run on the firm's own machine.
- A checked quote is what makes the answer usable for a lawyer.

## Common mistakes
- Meaning search alone → misses clause numbers. Add keyword search.
- Judging only the final answer → measure recall@k separately.
- Treating retrieved text as instructions → it is data. A contract can say "ignore previous instructions."
- Filtering access after search → filter by client or matter during search.

## Check your understanding
**Q: A lawyer asks "what does 7.2(b) say?" and meaning search returns the wrong clause. Why?**
A: Embeddings capture meaning, not exact strings like "7.2(b)". Keyword search finds it, which is why we use both.

**Q: Why add a one-line label to each chunk?**
A: The clause text alone doesn't say which contract or section it is from. The label carries that, so search can match it.

**Q: Why fetch a wide pool and then rerank?**
A: Fast search is noisy. A wide pool makes sure the right chunk is in it; the slower reranker moves it to the top.
