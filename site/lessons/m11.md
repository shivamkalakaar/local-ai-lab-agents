## Learning objective
- Improve a small local model's prompt with GEPA, and know when to move on to training.

## Prompt wording matters
| Prompt for PaLM 2-L-IT (math) | Score |
|---|---|
| "Let's think step by step." | 71.8% |
| "Let's combine our numerical command and clear thinking..." | 74.5% |
| "Take a deep breath and work on this problem step-by-step." | 80.2% |

- Small wording changes move the score. An optimizer can search for the best wording.

## Three pillars of optimization
- Data: training examples, rollouts, human feedback.
- System: the model, workflow or agent you tune.
- Metric: pass rate, exact match, LLM judge, cost.
- You need all three. No trustworthy metric, no optimization.

## Context vs weight optimization
| Context (prompt) optimization | Weight optimization |
|---|---|
| Changes the instructions and examples | Changes the model's numbers by training |
| Sample-efficient; fast; simple setup | Data hungry; grows with thousands of examples |
| Works with API-only models | Needs a model you can train |
| Our case: a better prompt for Llama 3.2 3B | Fallback if prompts plateau |

- Try prompts first. They are cheaper.

## GEPA: reflective prompt evolution
- Student: the small fast model doing the task (Llama 3.2 3B).
- Reflection model: a bigger model that reads the student's mistakes and rewrites the instructions (Llama 3.1 8B).
- Pareto set: GEPA keeps several strong candidates, not just one.
- Course demo: Gemma 3 12B went from 55% to 100% on a held-out set. Only the instruction text changed.

## Our task: three numbers from two clauses
| Clause (msa_13) | Correct output |
|---|---|
| "...automatically renew for successive one (1) year periods unless either party gives at least 15 days' prior written notice..." | renewal_years = 1, notice_days = 15 |
| "...SHALL NOT EXCEED THE FEES PAID BY CUSTOMER IN THE 12 MONTHS PRECEDING THE CLAIM." | cap_months = 12 |

- cap_months is 0 if liability is unlimited.

## Feedback, not just a score
| Bare score | Text feedback |
|---|---|
| 0.67 | "Wrong -> notice_days: expected 15, got 30" |
| Reflection model knows something failed | Reflection model knows what to fix |

- GEPA learns from the text. Vague "Wrong." usually gives smaller gains.

## Three data splits
- Train: 7 contracts. GEPA learns from these.
- Validation: 4 contracts. GEPA picks the best candidate on these.
- Test: 9 contracts. Hidden until the end. This is the honest score.
- Budget: `max_metric_calls`, how many times the metric may run.

## Running GEPA in code
```python
gepa = dspy.GEPA(metric=metric, max_metric_calls=60, reflection_lm=teacher, track_stats=True)
optimized = gepa.compile(program, trainset=train, valset=val)
after = evaluate(optimized, test)
print(f"held-out test: {before:.0%} -> {after:.0%}")
```
- Line 1: our metric, a budget of 60 calls, the 8B model reflects.
- Line 2: learn on train, pick the winner on validation.
- Line 3: score the winner on the hidden test set.
- Line 4: print before and after. About 10–15 minutes on a T4.

## The ladder after prompts
- SFT (supervised fine-tuning): train on a teacher's outputs that pass your checker.
- On-policy distillation: the student writes, the teacher scores every token. Needs an open-weight teacher.
- RL with GRPO: sample a group of answers; push toward those above the group average. Only where answers can be checked automatically.
- Then re-tune prompts on the new model (prompts → weights → prompts).

## How this applies to us
- Student and reflection model both run on the firm's machine. No client data leaves.
- The result is text: read it, version it (`renewal_terms_gepa.json`), roll it back.
- A tuned small model is faster and cheaper to run in-house.

## Common mistakes
- Optimizing on a weak metric → the optimizer finds every loophole. Fix the metric first.
- Feedback that only says "wrong" → say what was expected and what came back.
- Peeking at the test set → GEPA uses train and validation only.
- Training too early → in one course example, instruction-following fell from 85% to 45% after narrow training. Run a general check.

## Check your understanding
**Q: Our local model gets 70% on clause extraction. What do we try first?**
A: GEPA prompt optimization with a metric that gives text feedback. Build a training set only if that plateaus.

**Q: Why does the metric return a sentence, not just a number?**
A: "Expected 15, got 30" shows the reflection model what to fix. A number only says something is wrong.

**Q: Why does on-policy distillation need an open-weight teacher?**
A: It needs the teacher's score for every token. Closed APIs don't return those.
