## The big idea

Picture a test kitchen. A cook keeps a binder of every recipe tried so far, each with a taste score. Each day they pick a good recipe, change one thing, cook it, and have it tasted. Good results go in the binder. Bad ones are noted and rarely tried again. Over months, the binder fills with better and stranger dishes.

That is open-ended evolution with AI. A language model proposes changes to code, to an agent, or to an experiment. A program scores every proposal. An archive (the stored set of every candidate tried, with its score) keeps what worked, so the next round can build on it.

The surprising lesson is where the progress comes from. The model only supplies guesses. The real work is done by the scorer and the archive. A good scorer turns a stream of cheap guesses into steady improvement.

## Why it matters for us

- Small local models make lots of wrong guesses. This loop doesn't mind. If a cheap model can make many tries and a program can score them, you can still find good answers on your own computers.
- A law firm has checkable tasks. A set of contracts with known correct flags can score any new review agent automatically. That means the firm could search for a better agent design instead of hand-tuning prompts.
- The danger is real too. These loops run code the model wrote. You must fence that code in.

## How it works, step by step

1. **Build the scorer first.** The scorer must check validity before quality. Validity means "is this even a legal answer?" Quality means "how good is it?" Skip the validity check and the search will find a cheat.

2. **Fence in the code.** Model-written code can loop forever or delete files. Run it in a sandbox (a separate, limited process or container with a timeout, no network, and limited disk). The AI Scientist paper (2024) reports their system edited its own code to raise its timeout, and once relaunched itself repeatedly.

3. **AlphaEvolve: evolve a program** (the AlphaEvolve paper, 2025). It keeps a database of programs. Each step it picks a parent, shows the model that parent plus a few strong "inspiration" programs, and asks for an improved version. A fast model makes many ideas. A stronger model makes fewer, better ones. Each child is tested in an evaluation cascade: a tiny, quick test first, and the full, costly test only for children that pass. This found a way to multiply two 4x4 complex matrices with 48 multiplications instead of 49, the first gain over Strassen's method in this setting in 56 years.

4. **ADAS: evolve the agent itself** (the ADAS paper, 2024). Here each agent is written as code: a function that may call the model several times. A meta agent (an agent whose job is to write other agents) reads the archive of earlier designs and their scores. It writes a new design. That design is tested and added to the archive. The archive starts with known designs like "think step by step". The follow-up Darwin Gödel Machine paper (2025) applied the same idea to a coding agent that edits its own code, raising its score on a coding benchmark from 20.0% to 50.0%.

5. **The AI Scientist: evolve research.** It chains the whole research process: idea, experiment code, run, write-up, then an automated review. The authors report under $15 per paper. The weak points are the model acting as reviewer and the sandbox.

6. **Keep the whole archive, not only the best.** A candidate that looks worse today can be a stepping stone to a big win later. Open-endedness means rewarding what is new and interesting, not only what scores highest, so the search doesn't get stuck.

```
pick parent from archive -> model proposes change -> sandbox runs it
        ^                                                  |
        |                                                  v
   store child + score  <---- quick test -> full test (if it passed)
```

## Worked example

The firm wants a better clause-review agent. It has 50 past contracts, each with the correct flags from its playbook. For example: "liability cap at most 12 months of fees".

The archive starts with two designs. One asks the model once. One asks it to think step by step first. Each is scored by how many flags it gets right.

The meta agent reads both designs and their scores. It proposes a third: "first find the liability clause, then compare it to the rule in a second call." The sandbox runs it on 10 contracts as a quick test. It does fine, so it gets the full 50. It scores higher, and goes into the archive.

Now the warning. Suppose the scorer only counts "flags raised" and never checks they are correct. The search would soon find an agent that flags every clause. In the notebook's bin-packing version, a cheating program that overfills one bin scores 27 out of a "perfect" 1.0. The search optimizes what you measure, cheats included.

The other warning: a small test set lies. With 6 questions, one answer is worth about 17 points. A "winner" may just be lucky. Always confirm it on contracts the search never saw.

## Common mistakes

- **A scorer without a validity check.** The search will find the loophole. Check legality first, then quality.
- **Running model code in your own process.** Use a separate process or container with a timeout and no network.
- **Trusting a win on a tiny search set.** Keep a held-out set (data the search never touched) and trust only gains that show up there.
- **Keeping only the current best.** Without an archive and some variety, the search gets stuck on one line of ideas.
- **Letting a model reviewer be the only judge.** Check the write-up's numbers against the raw results with plain code.

## Check your understanding

**Q: Why does AlphaEvolve use an evaluation cascade instead of the full test on every child?**
A: Most children are worse or broken. A tiny quick test filters them out early, so the expensive test is spent only on promising ones.

**Q: In ADAS, what does the meta agent produce, and how is it judged?**
A: A new agent written as code. It is run on test tasks, and its score is stored with it in the archive.

**Q: Name two safety measures for an AI Scientist-style loop.**
A: Run generated code in a sandbox with time and storage limits and no network. Check the write-up's claims against the raw results with code, rather than trusting a model reviewer.
