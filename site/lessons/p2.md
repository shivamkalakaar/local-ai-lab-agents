## Learning objective
- Build an eval task in the Terminal-Bench layout, prove it is sound with four checks, and report pass@k and pass^k.

## Definitions
- Task: a single test with defined inputs and success criteria.
- Trial: one attempt at a task.
- Verifier: logic that scores the agent's work; writes a reward from 0 to 1.
- Oracle: the reference solution. Proves the task can be solved.
- Reward hacking: scoring well without doing the job.

## The four parts of a task
```
contract-flags/
  instruction.md        what the agent is asked to do (short, natural, fully specified)
  environment/          the files the agent starts with
  tests/test.py         HIDDEN verifier: runs after the agent, writes a reward from 0 to 1
  solution/solve.py     reference (oracle) solution: must score 1.0
```
- Our task: read contracts and the playbook, write `report.json` listing which rules each contract breaks.

## Terminal-Bench vs our task
| Terminal-Bench task | contract-flags |
|---|---|
| "output a STEP file in /app/out.step..." | "list which playbook rules each contract breaks" |
| `Dockerfile` copies `schematic.png` | `environment/`: contracts + `playbook.json` |
| `assert watertight()`, `assert correct_volume()` ... | `tests/test.py` compares `report.json` to the answer |

## The runner
- Each attempt gets a fresh temp folder with a copy of `environment/`. Tests are not copied.
- The verifier runs as a separate step after the agent stops.
- The reward file lives outside the agent's folder. The agent can't write its own score.
- Harbor uses Docker. Colab can't, so we use temp folders. Same idea.

## Test the task before any agent
| Fake agent | Must score | Why |
|---|---|---|
| Oracle | 1.0 | The task is solvable and the verifier works |
| Do nothing | 0 | Empty output can't pass |
| Different correct method | 1.0 | Verifier checks the result, not one style |
| Flag everything (shortcut) | under 0.5 | Reward hacking fails |

- Tasks are software. Software has bugs.

## Run the agent
- The agent is the Project 1 harness with three tools: list files, read a file, write a file.
- The tools only work inside its folder. It never sees the tests.
- Limits: 16 turns, 40,000-token budget. 5 attempts.

## Report like a benchmark
- Mean reward: average partial credit across contracts.
- pass@k: at least one of k attempts fully solved it.
- pass^k: every one of k attempts fully solved it. This is the number for repeated work.
- One success in five looks fine on pass@5 and scores 0% on pass^5.

## Second task: fee-check
| Input | Expected |
|---|---|
| msa_07, 2.1: "Customer shall pay Vendor $4,500 per month..." | Monthly fee: $4,500 |
| invoice_jan $4,500 · invoice_feb $5,000 · invoice_mar $4,500 | `mismatches.json`: `["invoice_feb.txt"]` |

- Shortcut: list every invoice → scores 0.

## The fee-check verifier in code
```python
want = json.loads((Path(__file__).parent / "expected.json").read_text())
p = ws / "mismatches.json"
try:
    got = json.loads(p.read_text()) if p.exists() else None
except json.JSONDecodeError:
    got = None
ok = isinstance(got, list) and sorted(got) == want
out.write_text("1.0" if ok else "0.0")
```
- Line 1: load the right answer; it sits next to the test, out of the agent's reach.
- Line 2: the file the agent was told to write.
- Lines 3–6: read it; missing file or broken JSON counts as nothing.
- Line 7: pass only if it is a list with exactly the right names.
- Line 8: write reward 1.0 or 0.0.

## How this applies to us
- A firm needs its own tests, from its own contracts and playbook, run on its own machine.
- The same four checks prove a firm's task is fair before any model is scored.
- pass^k tells the firm whether the local agent works every time.

## Common mistakes
- Testing the agent before the task → run the four soundness checks first.
- Agent can see or edit the tests → keep tests and reward outside its folder.
- Grading the steps → test the final result.
- Vague instructions → short and complete; one test per requirement.
- Reporting only pass@k → report pass^k too.

## Check your understanding
**Q: Why must a different correct solution also score 1.0?**
A: It proves the verifier checks the result, not one way of getting there.

**Q: The agent writes a "reward" file with 1.0 in its own folder. Full marks?**
A: No. The runner reads the reward from a file outside the agent's folder, written only by the verifier.

**Q: What is the difference between pass@k and pass^k?**
A: pass@k: at least one of k tries fully solved it. pass^k: all k tries did.
