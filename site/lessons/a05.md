## Learning objective
- Learn how a model trains on its own checked answers: STaR with fine-tuning, GRPO and DAPO with reinforcement learning.

## Why train-time scaling?
- a01–a04 spent more compute at answer time. Here we spend it at training time.
- Loop: the model tries, a checker grades, we train on what worked.
- Verifiable reward: a reward computed by a program (exact match, unit tests), not a person or a judge model.
  - Cheap, and hard to fool
- STaR: fine-tune on kept answers. GRPO and DAPO: reinforcement learning.

## STaR: the model writes its own training data
- Ask the model to reason and answer many problems.
- Keep the reasoning only when the final answer is right.
- Rationalization: for wrong ones, show the correct answer as a hint and ask it to explain.
  - Store that explanation without the hint
- Fine-tune on everything kept. Repeat.

## STaR results (Zelikman et al. 2022)
| CommonsenseQA dev | Accuracy |
|---|---|
| GPT-J 6B, fine-tuned to answer directly | 60.0% |
| GPT-J + STaR, no rationalization | 68.8% |
| GPT-J + STaR, with rationalization | 72.5% |
| GPT-3 fine-tuned (30x larger) | 73.0% |

- GSM8K: 10.7% vs 5.8% for direct fine-tuning.
- Risk: right answer, wrong reasoning. Spot-check rationalized examples.

## GRPO: grade against the group
- GRPO (Group Relative Policy Optimization): the RL method from DeepSeekMath.
- Sample a group of answers per prompt (64 in the paper).
- Advantage: how much better one answer did than expected.
  - GRPO: (reward − group mean) / group spread
- Positive advantage → do more of this. Negative → do less.
- No critic model: the group mean replaces it, saving memory.

## PPO vs GRPO
| PPO | GRPO |
|---|---|
| A second network (critic) guesses the expected reward | The group's mean reward is the expected reward |
| More memory | No critic, less memory |
| One answer per prompt is enough | Needs a group of answers per prompt |

## GRPO on a contract question
| Rewards for 4 answers | Mean | Advantages | Teaches |
|---|---|---|---|
| [1, 1, 1, 0] | 0.75 | Right answers +, wrong one − | Shift toward the reasoning that worked |
| [1, 1, 1, 1] | 1.0 | All zero | Nothing |

- Question: "Is the liability cap at most 12 months of fees? End with Answer: yes or no."
- A program reads the last line and gives 1 if right.

## GRPO advantages in code
```python
def grpo_advantages(r, eps=1e-4):
    r = np.asarray(r, dtype=float)
    return (r - r.mean()) / (r.std() + eps)
```
- `r`: the rewards for one group; `eps`: a tiny number so we never divide by zero.
- Line 2: turn the list into an array of decimals.
- Line 3: subtract the group mean, divide by the spread. Grading on a curve.

## DeepSeekMath results (Shao et al. 2024)
- 7B model, continued pre-training on 120B math tokens, then GRPO.
- MATH: 51.7% without tools or voting; 60.9% with voting over 64 samples.
- GRPO alone: GSM8K 82.9% → 88.2%; MATH 46.8% → 51.7%.
- RL raised Maj@K but not Pass@K.
  - Makes good answers more reliable more than it teaches new skills

## DAPO: four fixes to GRPO (Yu et al. 2025)
| Fix | Problem it solves |
|---|---|
| Clip-higher: upper clip 0.28, lower 0.2 | Rare good tokens can't grow; model stops exploring |
| Dynamic sampling: drop all-equal groups | Those groups give zero gradient |
| Token-level loss: average over all tokens | A long bad answer counts the same as a short one |
| Overlong reward shaping: soft length penalty | Cut-off answers get 0 for the wrong reason |

- DAPO also drops the KL penalty.

## DAPO ablation (AIME 2024, Qwen2.5-32B)
| Recipe | Score |
|---|---|
| Naive GRPO | 30 |
| + overlong filtering | 36 |
| + clip-higher | 38 |
| + soft overlong punishment | 41 |
| + token-level loss | 42 |
| + dynamic sampling | 50 |

- Beat DeepSeek-R1-Zero-Qwen-32B (47) with 50% of the training steps.

## A real run on a free GPU
- Model: SmolLM2-360M-Instruct. Train only a LoRA adapter.
  - LoRA: small add-on matrices instead of all weights; fits a free GPU
- Rewards: +1.0 exact answer, +0.2 for the `Answer:` line, soft overlong penalty.
- Group size 8, 120 steps, DAPO settings in TRL (`loss_type="dapo"`, `epsilon_high=0.28`).
- T4 has no bfloat16: set `bf16=False`, use fp16.

## How this applies to us
- Many contract checks have a code checker: right clause, cap within 12 months, verdict present. That is a verifiable reward.
- GRPO with LoRA trains a small open model on the firm's own GPU.
- Keep training questions at the edge of what the model can solve, so groups aren't all-equal.

## Common mistakes
- Questions too easy or too hard → every group all-equal, zero advantages, nothing learned.
- A reward that can be gamed → check the answer format strictly.
- bf16 on a T4 → set `bf16=False`; use fp16 or fp32.
- Reading training reward as the result → compare held-out accuracy before and after.

## Check your understanding
**Q: A group of 4 answers gets rewards [1, 1, 1, 1]. What are the GRPO advantages, and what does DAPO do?**
A: All zero, so the group gives no gradient. DAPO's dynamic sampling drops it and samples another prompt.

**Q: In STaR, why is the hint removed before fine-tuning on a rationalized example?**
A: So the model learns to produce the reasoning from the question alone, as it must at test time.

**Q: What does GRPO use instead of PPO's critic model?**
A: The mean and spread of the rewards of the other answers sampled for the same prompt.
