PRIME: Planning with Reflective Iterative Multi-Agentic Exploration

Open in Colab
11 min readPlain-English lesson, then the deeper material

How a Stanford team let an agent pick the right thinking trick for each step of a plan, and why you must compare at the same call budget.

The big idea

There are many tricks to make a model think better. It can reflect on its own answer. It can refine a draft. Two copies can debate. Most teams pick one trick and use it everywhere.

Chelsea Zou, Samuel Liu and Jui Khankari (the poster also lists Miriam Cheng) asked a better question in their CS329A project, PRIME (Winter 2025). What if the agent picked the best trick for each step of the task?

Think of a head chef. They don't use the same method for every dish. Some get a quick sear. Some get slow tasting and adjusting. A good chef learns which method works for which dish, and keeps that knowledge for next time.

PRIME does this with a search method called Monte Carlo Tree Search (MCTS): try promising options, keep score of what worked, and spend more effort on the winners while still testing others now and then.

Why it matters for us

A contract review has many steps. Some are easy, like "find the governing-law clause." Some are hard, like "does this indemnity clause break the playbook rule on liability caps?"

  • Spending the same effort on every step wastes calls on the easy ones and starves the hard ones. Picking a method per step can help.
  • On a firm's own computers, model calls are cheap but not free. PRIME's lesson is to compare methods at the same number of calls. Otherwise "smarter" may just mean "tried more times."
  • A cheap test, called a reverse ablation, shows which part of a pipeline deserves the bigger model. You upgrade one part at a time and see which upgrade helps most.

How it works, step by step

  1. Plan. A planner splits the task into subgoals (smaller pieces of the job). Each subgoal gets a confidence score from the model.

  2. Choose an action at each step. PRIME can Drill down (break the subgoal up further), Solve it with a chosen tool (self-reflection, self-refinement or debate), or Backtrack (give up on this branch and go back).

  3. Pick which option to try with UCT. UCT stands for Upper Confidence bound for Trees. It is a simple score: how well this option has done so far, plus a bonus for options you haven't tried much. The bonus keeps the search curious.

  4. Score the result. In the paper, values mix a model's own score with self-consistency (whether repeated answers agree).

  5. Back up the score. The option's value becomes the running mean (average so far) of all its results. Good options rise. Bad ones sink.

PRIME used GPT-4o-mini inside the search and tested on PlanBench, WebShop and Game of 24, 60 questions each. In Table 1, PRIME scored 36.2% / 40% / 75%. LATS, an earlier tree-search agent, scored 2.2% / 38% / 44%. Plain GPT-4o-mini scored 0% on all three. A word of caution: the paper's text gives different figures for some of the same cells, so these numbers are not fully consistent. The authors estimate PRIME cost about 4x less than o1, even with more calls.

Two honest results matter most. On WebShop, PRIME and LATS nearly tied, and reflections were generic. And the search wandered when it was unclear whether a step had worked.

Worked example

Picture a paralegal with a budget of five model calls for one tricky clause. The plan lists three angles: compare the cap to fees, check carve-outs, check the time window. For each angle, the agent can answer directly, answer then reflect, or break the angle down further. After each try, a checker says pass or fail. The agent learns which angle-and-method pairs pay off.

Contract checks are rarely exact, so our notebook uses Game of 24 instead. You must use four numbers once each, with + − × ÷, to make 24. A code checker can grade every answer perfectly. That makes the reward clear, which is exactly when tree search shines.

Here is the heart of the selection loop:

uct = lambda a: a["V"] + C * math.sqrt(math.log(total) / a["N"])
arm = max(arms, key=uct)
ok, used = run_tool(arm["tool"], nums, steps, arm["left"], budget - calls)
calls += used
r = 1.0 if ok else 0.0
arm["V"] = (arm["V"] * arm["N"] + r) / (arm["N"] + 1); arm["N"] += 1; total += 1
  • An "arm" is one pairing of a first step and a tool, like "8 − 2 = 6, then reflect."
  • Line 1 is the UCT score. V is how well the arm has done. The square-root part is the curiosity bonus. It is big when the arm N has been tried rarely. C sets how curious to be.
  • Line 2 picks the arm with the highest score.
  • Line 3 runs the tool and reports success and how many calls it used.
  • Line 4 counts calls against the budget of 5.
  • Line 5 turns pass or fail into a reward of 1 or 0.
  • Line 6 updates the running mean, the same rule the paper uses.

The notebook runs PRIME-lite next to two baselines. One is a single call. The other is "retry with feedback," which also gets up to 5 calls. If PRIME-lite only beats the single call, the extra calls did the work, not the cleverness.

Common mistakes

  • Comparing at unequal budgets. A method with 5 calls will usually beat 1 call. Always include a simple retry baseline with the same budget.
  • Using tree search without a clear reward. If you can't tell whether a step worked, the search wanders. Use it where a checker exists.
  • Upgrading every part at once. Swap in the bigger model one part at a time. That shows where the money should go.
  • Trusting one table. The PRIME paper's own numbers disagree in places. Read results with care and rerun what matters.

Check your understanding

What does the curiosity bonus in UCT do?

It raises the score of options that haven't been tried much. That stops the search from locking onto its first favorite too early.

Why does the notebook include a "retry with feedback" baseline?

It uses the same 5-call budget as PRIME-lite. If they tie, the gain came from extra tries, not from smart strategy choice.

Where did PRIME struggle?

On WebShop it nearly tied with LATS, and its reflections were generic. It also wandered when a step's value was unclear.

Problem
Reasoning tricks such as reflection, debate and voting are applied ad hoc, with no principled way to choose the right one for each step of a multi-step plan.
Method
Treat each reasoning technique as an 'option' and search with Monte Carlo Tree Search. A planner splits the task into subgoals; at each node it can Drill down, Solve with the best-suited self-improvement tool (self-reflection, self-refinement, debate), or Backtrack. Values are backed up with a running mean and nodes chosen with UCT; non-leaf values mix an LM score with self-consistency. Built on LATS. GPT-4o-mini inside PRIME, compared with LATS, plain 4o-mini and one-shot o1 on 60 sampled questions each from PlanBench, WebShop and Game of 24, plus a reverse ablation that upgrades only the planner or only the executor.
Results
Table 1 success rates (PlanBench / WebShop / Game of 24): PRIME 36.2% / 40% / 75%; LATS 2.2% / 38% / 44%; GPT-4o-mini 0% / 0% / 0%; GPT-o1 100% / 100% / 100%; PRIME with upgraded planner 95% / 94% / 100%; with upgraded executor 96% / 92% / 100%. The text gives different figures for some cells (PRIME 'a 2.2% improvement over LATS' on PlanBench; o1 at 37.3% on PlanBench and 80% on WebShop), so these numbers are internally inconsistent. Estimated about 4x lower cost than o1 despite more API calls.
Lessons
Choosing the strategy per subgoal can beat one fixed strategy, but compare at equal call budgets: on WebShop, PRIME and LATS tied and reflections were generic. Tree search shines when each step's result is clear and checkable, and wanders when it isn't. A reverse ablation (upgrade one component at a time) is a cheap way to find which part of a pipeline deserves the expensive model.
Our rebuild
Game of 24 with an exact ast-based checker. PRIME-lite: the planner proposes first steps with a confidence (LM value); code drops impossible steps (backtrack); a bandit-style MCTS picks (subgoal, tool) arms with UCT across three tools (solve, reflect, drill down), uses the checker as reward, backs up values with the paper's running mean, and carries tool statistics across puzzles. Compared at a 5-call budget against single-shot and retry-with-feedback; solutions run a reverse ablation with a 3B executor and vary the exploration constant.

The original project

PRIME: Planning with Reflective, Iterative, Multi-agentic Exploration by Chelsea Zou, Samuel Liu and Jui Khankari (the poster lists Chelsea Zou, Jui Khankari and Miriam Cheng). Stanford CS329A, Winter 2025. Paper · Poster

Problem. Top-down planning with LLMs is unsolved. Reflection, debate and voting are used "ad hoc", with no principled way to pick the right one for a given step.

Method. Treat each reasoning technique as an option (a reusable sub-policy, from reinforcement learning) and search with Monte Carlo Tree Search (MCTS). A planner splits the problem into N subgoals (tree children). At each node it chooses Drill down (split further), Solve (call the best-suited self-improvement tool: self-reflection, self-refinement or debate) or Backtrack (drop a useless subgoal). Results flow back up the tree with a running mean, V(s) ← (V·N + r)/(N+1), and the next node is chosen with UCT = w/n + C·√(ln N / n). Leaves are judged by ground truth when it exists, otherwise by V(s) = λ·LM(s) + (1−λ)·SC(s), a mix of a model's score and self-consistency. It builds on LATS (Zhou et al. 2024, Language Agent Tree Search).

Setup. GPT-4o-mini inside PRIME vs. LATS (4o-mini), plain 4o-mini, and one-shot GPT-o1, on 60 sampled questions each from PlanBench, WebShop and Game of 24. Plus a "reverse ablation": upgrade only the planner, or only the executor, to a stronger model.

Limitations they state. PRIME wanders when the value of an action is unclear (obfuscated PlanBench); on WebShop, reflections were generic and the agent got stuck in local minima, so subgoals helped little.

Our mini version. Game of 24 only, because a checker can grade it exactly. The planner proposes first steps with a confidence (the LM value). Code rejects impossible steps (backtrack). A small bandit-style MCTS picks a (subgoal, tool) pair with UCT, where the tools are solve, reflect and drill down. The checker is the reward. Tool statistics carry over from puzzle to puzzle, a tiny version of "learning which option works".

1. The task and an exact checker

Use each of four numbers once with + − × ÷ to make 24. The checker parses the expression with Python's ast module (no eval), checks the numbers used, and computes with exact fractions.

ap2_prime.ipynb · cell 3
OPS = {ast.Add: lambda a, b: a + b, ast.Sub: lambda a, b: a - b, ast.Mult: lambda a, b: a * b, ast.Div: lambda a, b: a / b}

def evaluate(node, used):
    if isinstance(node, ast.Expression):
        return evaluate(node.body, used)
    if isinstance(node, ast.Constant) and isinstance(node.value, int) and not isinstance(node.value, bool):
        used.append(node.value); return Fraction(node.value)
    if isinstance(node, ast.BinOp) and type(node.op) in OPS:
        return OPS[type(node.op)](evaluate(node.left, used), evaluate(node.right, used))
    raise ValueError("only whole numbers, + - * / and brackets are allowed")

def check24(expr: str, nums) -> tuple:
    """(ok, message). The message is what a reflecting agent gets to see."""
    try:
        used = []
        val = evaluate(ast.parse(expr, mode="eval"), used)
    except ZeroDivisionError:
        return False, "it divides by zero"
    except Exception as e:
        return False, f"it is not a valid expression ({e})"
    if sorted(used) != sorted(nums):
        return False, f"it uses the numbers {sorted(used)} but must use exactly {sorted(nums)}"
    if val != 24:
        return False, f"it equals {val}, not 24"
    return True, "correct"

def extract_expr(text: str) -> str:
    text = (text or "").replace("×", "*").replace("÷", "/").replace("−", "-")
    m = re.findall(r"ANSWER:\s*(.+)", text, re.I)
    cand = m[-1] if m else (text.strip().splitlines() or [""])[-1]
    cand = re.sub(r"(?<=[\d\)])\s*[xX]\s*(?=[\d\(])", "*", cand)
    parts = [p for p in cand.split("=") if re.search(r"\d", p)]
    if len(parts) > 1 and re.fullmatch(r"\s*24\s*\.?\s*", parts[-1]):
        parts = parts[:-1]
    cand = max(parts, key=lambda p: len(re.findall(r"\d+", p))) if parts else ""
    return re.sub(r"[^\d\s\+\-\*/\(\)]", "", cand).strip()

def solve24(nums):
    """Brute force: returns one solution or None. Used only to pick solvable puzzles, never by the agents."""
    items = [(Fraction(n), str(n)) for n in nums]
    def rec(items):
        if len(items) == 1:
            return items[0][1] if items[0][0] == 24 else None
        for i, j in itertools.permutations(range(len(items)), 2):
            (a, ea), (b, eb) = items[i], items[j]
            rest = [items[k] for k in range(len(items)) if k not in (i, j)]
            for v, e in [(a + b, f"({ea}+{eb})"), (a - b, f"({ea}-{eb})"), (a * b, f"({ea}*{eb})")] + \
                        ([(a / b, f"({ea}/{eb})")] if b != 0 else []):
                r = rec(rest + [(v, e)])
                if r:
                    return r
        return None
    return rec(items)

rng = random.Random(329)
PUZZLES = []
while len(PUZZLES) < 6:
    nums = sorted(rng.randint(1, 13) for _ in range(4))
    if nums not in PUZZLES and solve24(nums):
        PUZZLES.append(nums)
print(PUZZLES)
print(check24("(8-2)*(3+1)", [1, 2, 3, 8]), check24("8*3", [1, 2, 3, 8]), extract_expr("So: (8 − 2) × (3 + 1) = 24\nANSWER: (8-2)*(3+1) = 24"))

2. Baselines: one shot, and retry with feedback (same budget as PRIME)

The retry baseline is a plain reflection loop: try, get the checker's message, try again. If PRIME only wins because it makes more calls, this baseline will catch it.

ap2_prime.ipynb · cell 4
BUDGET = 5            # model calls per puzzle for the two search methods
ASK24 = ("Use each of the numbers {nums} exactly once, with + - * / and brackets, to make exactly 24.\n"
         "Think briefly, then end with one line: ANSWER: <expression>")

def single_shot(nums):
    out = ask(ASK24.format(nums=nums), max_tokens=600)
    ok, _ = check24(extract_expr(out), nums)
    return {"ok": ok, "calls": 1}

def retry_with_feedback(nums, budget=BUDGET):
    msgs = [{"role": "user", "content": ASK24.format(nums=nums)}]
    for call in range(1, budget + 1):
        out = chat(msgs, temperature=0.7, max_tokens=600).content or ""
        expr = extract_expr(out)
        ok, why = check24(expr, nums)
        if ok:
            return {"ok": True, "calls": call}
        msgs += [{"role": "assistant", "content": out},
                 {"role": "user", "content": f"Your expression '{expr}' is wrong: {why}. Reflect on the mistake and try a different approach."}]
    return {"ok": False, "calls": budget}

3. PRIME-lite

  • Plan (1 call): propose up to 4 first steps like 8 - 2 = 6, each with a confidence 1–10.
  • Backtrack for free: code drops steps that use numbers we don't have or have wrong arithmetic.
  • Options for each surviving subgoal: solve (1 call), reflect (solve, and if the checker says no, fix once: up to 2 calls), drill (propose the next step, code checks it, then solve with both steps fixed: 2 calls).
  • Select the (subgoal, option) arm with the highest UCT score, run it, get reward 1 or 0 from the checker, update the arm with the running mean from the paper. Stop on success or when the budget is used up.
  • Learn across puzzles: each option keeps a global success rate that becomes the starting value of new arms.
ap2_prime.ipynb · cell 5
class Subgoal(BaseModel):
    step: str = Field(description="one operation on two of the available numbers, like '8 - 2 = 6'")
    confidence: int = Field(ge=1, le=10, description="how likely this step leads to 24")

class Plan(BaseModel):
    subgoals: List[Subgoal] = Field(max_length=4)

def fmt(x: Fraction):
    return str(x.numerator) if x.denominator == 1 else f"{x.numerator}/{x.denominator}"

def apply_step(step: str, state):
    """Check one step against the available numbers. Returns (new_state, text) or None (= backtrack)."""
    m = re.search(r"(\d+(?:/\d+)?)\s*([\+\-\*/xX×÷])\s*(\d+(?:/\d+)?)", (step or "").replace("−", "-"))
    if not m:
        return None
    a, op, b = Fraction(m.group(1)), m.group(2), Fraction(m.group(3))
    pool = list(state)
    for v in (a, b):
        if v not in pool:
            return None
        pool.remove(v)
    op = {"x": "*", "X": "*", "×": "*", "÷": "/"}.get(op, op)
    if op == "/" and b == 0:
        return None
    val = {"+": a + b, "-": a - b, "*": a * b, "/": a / b if b else None}[op]
    return pool + [val], f"{fmt(a)} {op} {fmt(b)} = {fmt(val)}"

SOLVE = ("Numbers: {nums}. Goal: 24, using each number exactly once with + - * / and brackets.\n"
         "Follow this plan: {steps}. After these steps the numbers left are {left}.\n"
         "Write ONE expression with the ORIGINAL numbers {nums} that follows the plan and equals 24.\n"
         "End with one line: ANSWER: <expression>")

class Step(BaseModel):
    step: str

TOOL_STATS = {t: [1, 2] for t in ("solve", "reflect", "drill")}     # [successes+1, tries+2]: a gentle prior

def run_tool(tool, nums, steps, left, budget_left):
    """Returns (ok, calls_used)."""
    prompt = SOLVE.format(nums=nums, steps="; ".join(steps), left=[fmt(x) for x in left])
    if tool == "drill":
        try:
            nxt = structured(f"Numbers left: {[fmt(x) for x in left]}. Goal: reach 24 in the end. "
                             f"Propose the single best next step on two of these numbers, like 'a op b = c'.", Step, temperature=0.7)
            res = apply_step(nxt.step, left)
        except Exception:
            res = None
        if res is None or budget_left < 2:
            return False, 1
        left, txt = res
        prompt = SOLVE.format(nums=nums, steps="; ".join(steps + [txt]), left=[fmt(x) for x in left])
        ok, _ = check24(extract_expr(ask(prompt, temperature=0.3, max_tokens=500)), nums)
        return ok, 2
    msgs = [{"role": "user", "content": prompt}]
    out = chat(msgs, temperature=0.3, max_tokens=500).content or ""
    ok, why = check24(extract_expr(out), nums)
    if ok or tool == "solve" or budget_left < 2:
        return ok, 1
    msgs += [{"role": "assistant", "content": out},
             {"role": "user", "content": f"A checker says your expression is wrong: {why}. Reflect, then give a fixed ANSWER line."}]
    ok, _ = check24(extract_expr(chat(msgs, temperature=0.3, max_tokens=500).content), nums)
    return ok, 2

def prime(nums, budget=BUDGET, C=1.0, log=False):
    calls = 1
    try:
        plan = structured(f"Numbers: {nums}. Goal: make 24 using each number once with + - * /.\n"
                          "Propose up to 4 DIFFERENT promising first steps. Each step combines two of the numbers.",
                          Plan, temperature=0.7)
        subgoals = plan.subgoals
    except Exception:
        subgoals = []
    state0 = [Fraction(n) for n in nums]
    arms = []                                            # one arm per (valid subgoal, tool)
    for sg in subgoals:
        res = apply_step(sg.step, state0)
        if res is None:
            if log: print("   backtrack (invalid step):", sg.step)
            continue
        left, txt = res
        for tool, (s, n) in TOOL_STATS.items():
            prior = 0.5 * sg.confidence / 10 + 0.5 * s / n   # V = λ·LM + (1−λ)·(what this option did before)
            arms.append({"txt": txt, "left": left, "tool": tool, "N": 1, "V": prior})
    if not arms:                                         # nothing valid: fall back to solving from scratch
        arms = [{"txt": "(no plan)", "left": state0, "tool": "reflect", "N": 1, "V": 0.5}]
    total = sum(a["N"] for a in arms)
    while calls < budget:
        uct = lambda a: a["V"] + C * math.sqrt(math.log(total) / a["N"])
        arm = max(arms, key=uct)
        steps = [] if arm["txt"] == "(no plan)" else [arm["txt"]]
        ok, used = run_tool(arm["tool"], nums, steps, arm["left"], budget - calls)
        calls += used
        r = 1.0 if ok else 0.0
        arm["V"] = (arm["V"] * arm["N"] + r) / (arm["N"] + 1); arm["N"] += 1; total += 1     # backpropagation
        TOOL_STATS[arm["tool"]][0] += r; TOOL_STATS[arm["tool"]][1] += 1
        if log: print(f"   try {arm['tool']:7s} on [{arm['txt']}] -> {'✓' if ok else '✗'} (calls {calls})")
        if ok:
            return {"ok": True, "calls": calls}
    return {"ok": False, "calls": calls}

print(apply_step("8 - 2 = 6", [Fraction(n) for n in (1, 2, 3, 8)]), apply_step("9 - 2", [Fraction(n) for n in (1, 2, 3, 8)]))

4. Run all three methods

Puzzles run two at a time. Total model calls: at most 6 + 30 + 30.

ap2_prime.ipynb · cell 6
def run(method):
    with ThreadPoolExecutor(2) as ex:
        return list(ex.map(method, PUZZLES))

results = {"single shot": run(single_shot), "retry + feedback": run(retry_with_feedback)}
print("PRIME-lite, puzzle by puzzle:")
results["PRIME-lite"] = []
for nums in PUZZLES:                                   # sequential so tool statistics carry over in order
    print(" ", nums)
    results["PRIME-lite"].append(prime(nums, log=True))

for name, rs in results.items():
    acc = sum(r["ok"] for r in rs) / len(rs)
    calls = sum(r["calls"] for r in rs) / len(rs)
    print(f"{name:18s} success {acc:4.0%}   avg calls {calls:.1f}")
print("option statistics (successes+1, tries+2):", TOOL_STATS)

What to notice. With an 8B model the single shot is often weak, like 4o-mini's 0% in the paper. Compare PRIME-lite with retry + feedback, not just with the single shot: both spend up to 5 calls. If PRIME-lite wins, the plan + strategy choice is doing work. If they tie, the gain came from more tries, which is the honest result the paper's WebShop row also shows. Also look at the option statistics: which tool did the search learn to prefer?
