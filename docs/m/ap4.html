Towards Effective Meta-Agents: Designing Agents that Design Agents (paper: Inefficiencies of Meta Agents for Agent Design)

Open in Colab
11 min readPlain-English lesson, then the deeper material

How a Stanford team tested agents that design other agents, and why you should do the cost arithmetic before building one.

The big idea

A meta-agent is an agent that designs other agents. It writes a new agent, tests it, saves it in an archive (a list of every design so far with its score), and uses that archive to write the next one. It sounds like free progress.

Batu El, Mert Yuksekgonul and James Zou studied this loop in their CS329A project (Winter 2025). The course page calls it "Towards Effective Meta-Agents." The paper is titled "Inefficiencies of Meta Agents for Agent Design." They asked three hard questions about meta-agents like ADAS (the Automated Design of Agentic Systems paper, 2024):

  1. Does the meta-agent really learn from its past designs?
  2. Are the designs different enough to combine?
  3. Does the design cost ever pay for itself?

Think of hiring a consultant to redesign your intake process. The new process may be a bit better. But you paid the consultant, and the new process takes longer per client. You only come out ahead after enough clients.

Why it matters for us

A firm might want a system that keeps inventing better contract-review agents on its own. This project says: check the math first.

  • Designed agents often cost more per question, because they make more model calls. Add the cost of designing them, and they may never pay back.
  • Showing the designer everything it has tried can be worse than showing it only the best few.
  • Running on the firm's own computers lowers the price per call, but not the number of calls. The arithmetic still matters.

How it works, step by step

  1. Start with a library. The archive began with 7 hand-written agents, such as Chain-of-Thought (reason step by step), Majority Voting, LLM Debate and Step-back.

  2. Pick what the designer sees. This choice is called the context strategy. There were three:

  3. Cumulative: show all past agents (what ADAS does).
  4. Parallel: show only the 7 starting agents, so every new design starts fresh.

  5. Evolutionary: show the 7 best agents so far, like picking parents.

  6. Design, test, save. A gpt-4o meta-agent wrote agent code that ran on gpt-3.5. They repeated this for 30 rounds, on four test sets, 3 times each.

  7. Measure diversity. Each agent gets a row of right and wrong answers. Cosine similarity (a number for how alike two rows are; near 1 means the same questions right) shows whether agents overlap. Coverage is the share of questions at least one agent gets right.

  8. Do the cost math. Total cost is C0 + n × Cj. C0 is the one-time design cost. Cj is the cost per question once deployed. n is the number of questions.

What they found. Best training score, averaged: cumulative 55.0, parallel 60.0, evolutionary 60.3. So showing everything did not beat showing nothing new. Evolutionary gained up to 10 points over cumulative on MGSM (41.4 vs. 56.5). On test, the starting library scored 49.0, cumulative 52.2, parallel 55.9, evolutionary 55.2. Evolutionary agents were the least diverse.

The cost result is the sharpest. Designed agents cost more per question than the starting ones. Counting design cost, a designed agent was cheaper per correct answer only after about 15,000 questions. That happened only on MMLU and DROP with parallel context. Elsewhere it never broke even.

Worked example

Say the firm's best plain agent reviews a clause in a single call. A meta-agent designs a "solve then check" agent that makes two calls and is a bit more accurate. Is it worth it?

Our notebook asks the same question at small scale. Designs are data, not code: a system prompt plus one of four fixed procedures. So nothing the model writes is ever run as code. llama3.1:8b designs, llama3.2:3b runs the agents, on six kinds of checkable puzzles. Here is the break-even step:

C0 = sum(tok(a["chars"] + a.get("meta_chars", 0)) for a in designed)
c_init, c_new = tok(test_init["chars"]) / len(TEST), tok(test_new["chars"]) / len(TEST)
p_init, p_new = max(test_init["score"], 1e-9), max(test_new["score"], 1e-9)
gap = c_init / p_init - c_new / p_new
breakeven = C0 / (p_new * gap) if gap > 0 and best_new is not best_init else float("inf")
  • Line 1 adds up the design cost, C0. It counts the designer's prompts plus testing every new design. tok turns characters into tokens (about 4 characters each).
  • Line 2 finds the cost per question for the old agent and the new one.
  • Line 3 takes each agent's accuracy on the test set. The tiny number avoids dividing by zero.
  • Line 4 compares cost per correct answer. If the new agent is not cheaper per correct answer, the gap is zero or negative.
  • Line 5 finds how many questions it takes to earn back C0. If there is no gap, the answer is "never."

For the firm, swap in real numbers: clauses per month, tokens per review, and accuracy. If break-even is 15,000 clauses and you review 500 a month, that is years away.

Common mistakes

  • Skipping the cost math. A better score can still lose money. Compute break-even first.
  • Feeding the designer everything. The full history did worse than a curated set. Show the best few designs.
  • Expecting a "pick the best agent per question" boost. Designed agents tend to solve the same questions, so combining them adds little unless you push for variety.
  • Trusting one run. Results from small test sets are noisy. The authors used 3 runs; use several too.

Paper · Poster

Problem
Meta-agents such as ADAS write new agents in a sample-evaluate-iterate loop. Do they learn from past designs, are the designs diverse enough to combine, and is the design cost ever worth it?
Method
Archive starts with 7 hand-written agents (Chain-of-Thought, Majority Voting, Refinement from Feedback, LLM Debate, Quality-Diversity, Routing, Step-back). A gpt-4o meta-agent writes agent code run on gpt-3.5, for 30 iterations, with three context strategies: cumulative (all past agents, as in ADAS), parallel (only the initial library), evolutionary (top 7 so far). MGSM, DROP, MMLU (128 train / 200 test) and GPQA (32 / 160), 3 runs. Diversity via cosine similarity of per-question score vectors and coverage; economics via total cost C0 + n*Cj.
Results
Best agent's train score, averaged over datasets: cumulative 55.0, parallel 60.0, evolutionary 60.3 (cumulative did not beat parallel). Evolutionary up to +10 points over cumulative on MGSM (41.4 vs. 56.5 train). Test score of the best-on-train agent, average: initial library 49.0, cumulative 52.2, parallel 55.9, evolutionary 55.2. Coverage average: cumulative 94.2%, parallel 95.9%, evolutionary 94.4%; evolutionary agents were the least diverse. Designed agents cost more per query than the initial ones (cumulative > evolutionary > parallel > initial). The designed agent becomes cheaper per correct answer only after about 15,000 queries, and only on MMLU and DROP with parallel context; elsewhere never.
Lessons
Before building a self-improving agent designer, do the cost arithmetic: design cost plus higher per-query cost often never pays back. Showing the meta-agent everything it has tried can be worse than showing nothing; curate the context (best parents). Designed agents tend to be similar, so 'pick the best per query' gains are limited unless you push for diversity. Meta-evaluation is noisy; use several runs.

The original project

Listed on the course page as Towards Effective Meta-Agents: Designing Agents that Design Agents. The linked paper is titled Inefficiencies of Meta Agents for Agent Design, by Batu El, Mert Yuksekgonul and James Zou (Stanford); the poster is titled Exploring Two Open Questions in Meta-Agent Design. Stanford CS329A, Winter 2025. Paper · Poster

Problem. Meta-agents such as ADAS (Hu et al. 2024, Automated Design of Agentic Systems) follow a sample–evaluate–iterate loop. Is that loop efficient?

Method. An agent is code that takes a question and calls a model. The archive starts with 7 hand-written agents: Chain-of-Thought, Majority Voting, Refinement from Feedback, LLM Debate, Quality-Diversity, Routing, and Step-back. Each round, the meta-agent (gpt-4o) writes a new agent conditioned on a chosen part of the archive; agents run on gpt-3.5. Three ways to choose that context: - Cumulative: show all previous agents (what ADAS does). - Parallel: show only the 7 starting agents, so every sample is independent. - Evolutionary: show the 7 best agents so far (the "parents").

Setup. MGSM, DROP, MMLU (128 train / 200 test each) and GPQA (32 train / 160 test), 30 iterations, 3 runs.

Key results (as reported). - Best agent's train score, averaged over datasets: cumulative 55.0, parallel 60.0, evolutionary 60.3. "Cumulative context curation does not outperform parallel", that is, showing all past designs was worse than showing none. Evolutionary gave up to +10 points over cumulative on MGSM (41.4 → 56.5 train). - Test score of the best-on-train agent, average: initial library 49.0, cumulative 52.2, parallel 55.9, evolutionary 55.2. - Diversity: designed agents get many of the same questions right. Evolutionary agents are the most similar; parallel gives the most coverage (questions solved by at least one agent): 95.9% on average vs. 94.2 cumulative, 94.4 evolutionary. - Cost: designed agents cost more per query than the starting agents (cumulative > evolutionary > parallel > initial). Counting the design cost, the designed agent is cheaper per correct answer only after about 15,000 queries, and only on MMLU and DROP with parallel context. On the other datasets it never breaks even.

Limitations they state. Only this one class of meta-agent; accuracy/F1 only; cost analysis fits tasks with strong verifiers; cosine similarity favors high-scoring agents; only 3 runs because each run is expensive.

Our mini version. Designs are data (a system prompt plus one of four fixed procedures), not free-form code, so nothing the model writes is ever executed. llama3.1:8b plays the meta-agent and llama3.2:3b runs the agents, mirroring their strong-designer / cheap-runner split. We use evolutionary context, measure diversity and coverage, and compute the break-even point with the paper's formula: total cost = C0 + n·Cj.

1. A small, mixed task set with exact checkers

Six kinds of questions where small models stumble in different ways: counting letters, reversing words, sorting, weekday arithmetic, word problems, and comparing decimals. Mixed kinds give designs a chance to specialize.

ap4_meta_agents.ipynb · cell 3
WORDS = ["strawberry", "banana", "committee", "bookkeeper", "mississippi", "parallel", "assessment", "balloon", "occurrence"]
DAYS = ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]
KINDS = ["count", "reverse", "sort", "weekday", "math", "compare"]

def make_task(rng, kind):
    if kind == "count":
        w = rng.choice(WORDS); ch = rng.choice(sorted(set(w)))
        return dict(kind=kind, q=f"How many times does the letter '{ch}' appear in the word '{w}'?", a=str(w.count(ch)))
    if kind == "reverse":
        w = rng.choice(WORDS)
        return dict(kind=kind, q=f"Write the word '{w}' backwards (its letters in reverse order).", a=w[::-1])
    if kind == "sort":
        nums = rng.sample(range(1, 99), 6)
        return dict(kind=kind, q="Sort these numbers from smallest to largest: " + ", ".join(map(str, nums)), a=",".join(map(str, sorted(nums))))
    if kind == "weekday":
        s, k = rng.randrange(7), rng.randint(9, 60)
        return dict(kind=kind, q=f"Today is {DAYS[s]}. What day of the week will it be in {k} days?", a=DAYS[(s + k) % 7].lower())
    if kind == "math":
        a, b = rng.randint(6, 24), rng.randint(3, 12); c = rng.randint(5, a * b - 1)
        return dict(kind=kind, q=f"A crate holds {a} bottles. A shop gets {b} crates and sells {c} bottles. How many bottles are left?", a=str(a * b - c))
    x = rng.randint(1, 9); p, q = f"{x}.{rng.randint(10, 99)}", f"{x}.{rng.randint(1, 9)}"
    return dict(kind=kind, q=f"Which number is larger: {p} or {q}? Answer with the number.", a=max(p, q, key=float))

rng = random.Random(42)
TRAIN = [make_task(rng, k) for k in KINDS]
TEST = [make_task(rng, k) for k in KINDS[:4]]      # 4 test tasks keeps the notebook within ~80 model calls

def final_answer(text):
    m = re.findall(r"ANSWER:\s*(.+)", text or "", re.I)
    if m:
        return m[-1].strip()
    lines = (text or "").strip().splitlines()
    return lines[-1] if lines else ""

def correct(task, text):
    got = final_answer(text or "")
    if task["kind"] == "sort":
        return re.findall(r"\d+", got) == task["a"].split(",")
    if task["kind"] in ("reverse", "weekday"):
        return re.sub(r"[^a-z]", "", got.lower()) == task["a"]
    nums = re.findall(r"-?\d+(?:\.\d+)?", got)
    return bool(nums) and abs(float(nums[0]) - float(task["a"])) < 1e-9

for t in TRAIN:
    print(f"{t['kind']:8s} {t['a']:>20s}  ← {t['q']}")
print(correct(TRAIN[0], f"so... ANSWER: {TRAIN[0]['a']}"), correct(TRAIN[2], "ANSWER: 1, 2"))

2. What an "agent design" is here, and the interpreter that runs it

A design is a name, a one-line idea, a system prompt, and a procedure from a fixed menu. The interpreter counts calls and characters, so we can do cost accounting later (tokens ≈ characters / 4).

ap4_meta_agents.ipynb · cell 4
class Design(BaseModel):
    name: str
    idea: str = Field(description="one or two sentences: why this design should work")
    system_prompt: str = Field(description="instructions for the agent, under 120 words")
    procedure: Literal["direct", "think_step_by_step", "solve_then_check", "plan_then_solve"]

FMT = "\nEnd with one line: ANSWER: <your final answer>"

def run_agent(d: Design, q: str):
    """Returns (text, calls, chars)."""
    sp = d.system_prompt[:1200]
    chars, calls = 0, 0
    def call(prompt):
        nonlocal chars, calls
        try:
            out = ask(prompt, system=sp, model_name=RUNNER, temperature=0, max_tokens=600)
        except Exception as e:
            out = ""
        chars += len(sp) + len(prompt) + len(out); calls += 1
        return out
    if d.procedure == "direct":
        out = call(q + FMT)
    elif d.procedure == "think_step_by_step":
        out = call(q + "\nThink step by step." + FMT)
    elif d.procedure == "solve_then_check":
        first = call(q + "\nThink step by step." + FMT)
        out = call(f"Question: {q}\nA first attempt:\n{first[-1500:]}\n\nCheck this attempt carefully, step by step. "
                   "If it is wrong, fix it." + FMT)
    else:  # plan_then_solve
        plan = call(f"Question: {q}\nWrite a short numbered plan for solving it. Do not solve it yet.")
        out = call(f"Question: {q}\nPlan:\n{plan[-1200:]}\nNow follow the plan." + FMT)
    return out, calls, chars

def evaluate(d: Design, tasks):
    with ThreadPoolExecutor(2) as ex:
        runs = list(ex.map(lambda t: run_agent(d, t["q"]), tasks))
    vec = [1.0 if correct(t, out) else 0.0 for t, (out, _, _) in zip(tasks, runs)]
    return {"vec": vec, "score": sum(vec) / len(vec), "calls": sum(r[1] for r in runs), "chars": sum(r[2] for r in runs),
            "fails": [(t["q"], final_answer(out)[:60], t["a"]) for t, (out, _, _), v in zip(tasks, runs, vec) if not v]}

4. The meta-agent loop: sample → evaluate → add to archive

select_context is the paper's φ. Evolutionary shows the best 3 designs so far with their scores and a few of their mistakes. Parallel shows only the starting library. Cumulative shows everything.

ap4_meta_agents.ipynb · cell 6
def select_context(archive, phi):
    if phi == "parallel":
        return [a for a in archive if a["origin"] == "initial"]
    if phi == "cumulative":
        return list(archive)
    return sorted(archive, key=lambda a: (a["score"], -a["chars"]), reverse=True)[:3]      # evolutionary: top-k parents

def describe(a):
    d = a["design"]
    fails = "; ".join(f"Q: {q[:70]} | gave: {g} | correct: {c}" for q, g, c in a["fails"][:3]) or "none"
    return (f"- name: {d.name}\n  idea: {d.idea}\n  procedure: {d.procedure}\n  system_prompt: {d.system_prompt}\n"
            f"  train score: {a['score']:.0%}\n  mistakes: {fails}")

META = ("You design AI agents. An agent is a system prompt plus one procedure:\n"
        "- direct: one call, answer immediately\n- think_step_by_step: one call with step-by-step reasoning\n"
        "- solve_then_check: two calls, solve then verify and fix\n- plan_then_solve: two calls, write a plan then follow it\n\n"
        "The agents answer short puzzles: counting letters, reversing words, sorting numbers, weekday arithmetic, "
        "word problems, comparing decimals.\n\nHere are existing agents and how they did:\n{ctx}\n\n"
        "Design ONE new agent that will score higher. Learn from the mistakes. Give concrete, task-specific tactics "
        "in the system prompt (for example: spell the word letter by letter). Use a new name.")

def meta_search(archive, phi, T):
    archive = list(archive)
    for t in range(T):
        ctx = "\n".join(describe(a) for a in select_context(archive, phi))
        try:
            d = structured(META.format(ctx=ctx), Design, model_name=DESIGNER, temperature=0.8, max_tokens=700)
        except Exception as e:
            print("meta-agent output was invalid:", e); continue
        r = evaluate(d, TRAIN)
        archive.append({"design": d, "origin": f"{phi} #{t + 1}", "meta_chars": len(ctx) + len(META) + len(d.model_dump_json()), **r})
        print(f"[{phi} {t + 1}] {d.name[:30]:30s} {d.procedure:18s} train {r['score']:.0%}")
    return archive

ARCHIVE = meta_search(ARCHIVE, "evolutionary", T)

5. Question 1: did search beat the starting library?

Pick the best design on the training set, then run it once on the held-out test set, next to the best starting agent.

6. Question 2: are the agents different enough to combine?

Each agent's row of right/wrong answers is its "embedding". Cosine similarity near 1 means two agents solve the same questions. Coverage is the share of questions that at least one agent solves: the ceiling for a perfect router.

ap4_meta_agents.ipynb · cell 8
def cosine(u, v):
    nu, nv = math.sqrt(sum(x * x for x in u)), math.sqrt(sum(x * x for x in v))
    return sum(x * y for x, y in zip(u, v)) / (nu * nv) if nu and nv else 0.0

vecs = [a["vec"] for a in ARCHIVE if any(a["vec"])]
pairs = [cosine(vecs[i], vecs[j]) for i in range(len(vecs)) for j in range(i + 1, len(vecs))]
coverage = sum(any(a["vec"][i] for a in ARCHIVE) for i in range(len(TRAIN))) / len(TRAIN)
print("agent  " + "  ".join(t["kind"][:5] for t in TRAIN))
for a in ARCHIVE:
    print(f"{a['design'].name[:22]:22s} " + "  ".join("  ✓  " if x else "  ·  " for x in a["vec"]))
print(f"mean pairwise similarity {sum(pairs) / max(len(pairs), 1):.2f}   coverage {coverage:.0%}   best single agent {max(a['score'] for a in ARCHIVE):.0%}")

7. Question 3: does the design cost ever pay off?

Cost in tokens (≈ characters / 4). C0 = everything spent to find the new agent: meta-agent prompts plus evaluating every designed agent on the training set. Cj = cost per query when deployed. After n queries: cost per correct answer = (C0 + n·Cj) / (n·accuracy). The starting agent has C0 = 0. The break-even n solves C0/(n·p_new) + C_new/p_new = C_init/p_init.

ap4_meta_agents.ipynb · cell 9
tok = lambda chars: chars / 4
C0 = sum(tok(a["chars"] + a.get("meta_chars", 0)) for a in designed)
c_init, c_new = tok(test_init["chars"]) / len(TEST), tok(test_new["chars"]) / len(TEST)
p_init, p_new = max(test_init["score"], 1e-9), max(test_new["score"], 1e-9)
gap = c_init / p_init - c_new / p_new
breakeven = C0 / (p_new * gap) if gap > 0 and best_new is not best_init else float("inf")
print(f"design cost C0 ≈ {C0:,.0f} tokens")
print(f"per query: starting agent {c_init:,.0f} tokens at {p_init:.0%}; designed agent {c_new:,.0f} tokens at {p_new:.0%}")
print("break-even after", "never (the designed agent is not cheaper per correct answer)" if math.isinf(breakeven) else f"{breakeven:,.0f} queries")

What to notice. On a handful of tasks, a lucky design can look great on train and slip on test: that's the paper's warning about noisy meta-evaluation, and why they averaged 3 runs. Two-call designs often win on accuracy but double the per-query cost, so the break-even point can be "never". Before you build a meta-agent, do this arithmetic.

# 1. Parallel context (RUN_LONG only, ~3 meta calls + up to 36 agent calls).
if RUN_LONG:
    par = meta_search([a for a in ARCHIVE if a["origin"] == "initial"], "parallel", T)
    par_new = [a for a in par if a["origin"] != "initial"]
    pv = [a["vec"] for a in par_new if any(a["vec"])]
    pp = [cosine(pv[i], pv[j]) for i in range(len(pv)) for j in range(i + 1, len(pv))]
    print("parallel: best train", max(a["score"] for a in par_new), " mean similarity", round(sum(pp) / max(len(pp), 1), 2))
else:
    print("Set RUN_LONG = True to compare with parallel context.")

# 2. A per-kind router. Notice: on training data the router can match coverage, but with one task per kind it is
#    "choosing on the test set". A real router needs its own held-out data, which is why agent selection is hard.
router = {}                                          # kind -> index of the chosen agent in ARCHIVE
for i, t in enumerate(TRAIN):
    router[t["kind"]] = max(range(len(ARCHIVE)), key=lambda j: (ARCHIVE[j]["vec"][i], -ARCHIVE[j]["chars"]))
router_score = sum(ARCHIVE[router[t["kind"]]]["vec"][i] for i, t in enumerate(TRAIN)) / len(TRAIN)
print({k: ARCHIVE[j]["design"].name for k, j in router.items()})
print(f"router {router_score:.0%} · best single {max(a['score'] for a in ARCHIVE):.0%} · coverage {coverage:.0%}")
