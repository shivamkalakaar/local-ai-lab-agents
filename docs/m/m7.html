DSPy: declare what, not the prompt

4/13
  • Signature (what): strict inputs and outputs, with types.
  • Module (how): composes signatures with program logic. dspy.Predict, dspy.ChainOfThought, dspy.ReAct.
  • Optimizer: improves the prompts or weights to raise a metric.

A DSPy signature

5/13
class ExtractCap(dspy.Signature):
    """Read a limitation-of-liability clause and extract the cap."""
    clause: str = dspy.InputField()
    cap_months: int | None = dspy.OutputField(desc="months of fees the cap equals; None if liability is unlimited")
    favorable_to_customer: bool = dspy.OutputField()
  • Line 1: names the task.
  • Line 2: the docstring becomes the instruction.
  • Line 3: input, the clause text.
  • Line 4: output, a whole number or None (no cap).
  • Line 5: output, yes/no.
  • No prompt written by hand. lm.inspect_history(n=1) shows the one DSPy sent.

DSPy module: model call + rule in code

6/13
  • CapReview runs dspy.ChainOfThought(ExtractCap) on the liability section.
  • Then code decides: issue = p.cap_months is None or p.cap_months > 12.
  • Notebook runs it on msa_02 (12 months) and msa_20 (36 months).
  • DSPy talks to the same local server: api_base="http://localhost:11434/v1".

LangGraph: state, nodes, edges

7/13
  • State: shared workspace the graph reads and writes (cid, clause, law, status).
  • Node: a function that reads and writes the state.
  • Edge: says which node runs next. Conditional edge: code picks the branch.
get clause → read law (model) → decide (code) → check law → END
                                       └──────→ needs human → END
  • check_law: California or Delaware → OK; anything else → ISSUE. msa_10 (Florida) should be ISSUE.

DSPy vs LangGraph

8/13
DSPy LangGraph
Signatures and modules State, nodes and edges
Best for pipelines you want to tune with an optimizer Best for mixing fixed steps, decisions and agent steps
ExtractCap → CapReview get → read → check or human

Durable steps: survive a crash

11/13
  • Temporal: activities are units that can fail; workflows link them; finished results are recorded.
  • Our version: SQLite, about 20 lines. Each step's result is stored under a hash of its name and arguments.
First run Rerun after a "crash"
Calls the model for each of 6 contracts Finds each saved result, no model call
Saves every result Same results; the check expects it faster

How this applies to us

12/13
  • For a small local model, the harness is a big part of the product. Pick it by measuring.
  • A firm reviewing many contracts should not restart from zero when the GPU runs out of memory.
  • Rules like "cap over 12 months is an issue" stay in code, outside the framework's prompt.

Common mistakes

13/13
  • Trusting a framework's hidden prompt → read it with inspect_history.
  • Picking a harness by reputation → measure success and cost on your task.
  • Metrics that return only a number → return "expected 12, got 24"; optimizers learn from it.
  • Model calls inside Temporal workflow code → replay breaks. Put them in recorded activities.

Check your understanding

In the LangGraph example, who decides whether a contract goes to a person?

Code. `decide` checks that the model's answer looks like a state name; if not, it routes to "needs human."

How do durable steps save time after a crash?

Each finished step's result is saved. On restart, the code reuses it instead of calling the model again.

Why must a Temporal workflow function avoid LLM calls?

Temporal replays workflow code to recover. LLM calls give different answers each time, so they go in activities whose results are recorded.

Lecture 5 · DSPy · LangGraph · Temporal · Arena, "HarnessTax" · course repo lecture5-frameworks

The harness is all the code around the model: the loop, tools, prompts, limits and logging. For weaker models it matters as much as the model itself. Pick it by measuring.

Key terms

Harness
All the code around the model: the loop, tools, prompts, context handling, limits and logging.Source: Lecture 5; Arena, "HarnessTax" (2026)
DSPy signature
A typed declaration of what goes into and comes out of an LM call (for example clause: str -> cap_months: int | None). DSPy writes the prompt.Source: Khattab et al., "DSPy", ICLR (2024)
DSPy module / optimizer
A module composes signatures with Python; an optimizer (such as GEPA or MIPROv2) improves prompts or examples against your metric.Source: Khattab et al. (2024); Lecture 5
LangGraph
A library for agents as graphs: shared state, nodes that update it, and edges (including conditional ones) that decide what runs next.Source: LangChain, "LangGraph Overview"
Durable execution
Recording each finished step so a crashed run resumes without repeating work or side effects (Temporal workflows and activities).Source: Lecture 5 (Temporal demo)

The three frameworks the course teaches

  • DSPy: you declare inputs and outputs (signatures), compose them in Python (modules), and an optimizer improves the prompts against your metric. Best for pipelines you want to tune.
  • LangGraph: state plus nodes plus edges. Good when you mix fixed steps and agent steps and want checkpoints.
  • Temporal: durable execution. Each LLM call is a retryable step; after a crash the workflow resumes without redoing finished steps.

1. DSPy: declare inputs and outputs, not prompts

A signature says what goes in and what comes out, with types. A module composes signatures with plain Python.

07_frameworks.ipynb · cell 3
lm = dspy.LM(f"openai/{MODEL}", api_base="http://localhost:11434/v1", api_key="local", temperature=0)
dspy.configure(lm=lm)

class ExtractCap(dspy.Signature):
    """Read a limitation-of-liability clause and extract the cap."""
    clause: str = dspy.InputField()
    cap_months: int | None = dspy.OutputField(desc="months of fees the cap equals; None if liability is unlimited")
    favorable_to_customer: bool = dspy.OutputField()

extract = dspy.Predict(ExtractCap)
s = next(x for x in sections(contract("msa_08")) if "Liability" in x["title"])
p = extract(clause=s["text"])
print(p)
print("truth:", labels()["msa_08"]["terms"]["liability_cap_months"])

A module mixes model calls with Python logic. Here code decides whether the cap breaks the playbook.

07_frameworks.ipynb · cell 4
class CapReview(dspy.Module):
    def __init__(self):
        self.extract = dspy.ChainOfThought(ExtractCap)
    def forward(self, cid):
        s = next(x for x in sections(contract(cid)) if "Liability" in x["title"])
        p = self.extract(clause=s["text"])
        issue = p.cap_months is None or p.cap_months > 12            # the rule lives in code
        return dspy.Prediction(cap_months=p.cap_months, issue=issue)

review = CapReview()
for cid in ["msa_02", "msa_20"]:
    print(cid, review(cid=cid))
print("\nThe exact prompt DSPy sent (always read it):")
lm.inspect_history(n=1)

2. LangGraph: state, nodes and edges

A graph with a fixed path plus one decision made by code: if extraction fails, skip straight to "needs human".

07_frameworks.ipynb · cell 5
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model=MODEL, base_url="http://localhost:11434/v1", api_key="local", temperature=0)

class State(TypedDict, total=False):
    cid: str; clause: str; law: str; status: str

def get_law_clause(state):
    s = next(x for x in sections(contract(state["cid"])) if "Governing" in x["title"])
    return {"clause": s["text"]}

def read_law(state):
    out = llm.invoke(f"{state['clause']}\nWhich US state's law governs? Reply with the state name only.").content.strip()
    return {"law": out.rstrip(".")}

def decide(state):
    return "check" if state["law"] and len(state["law"]) < 20 else "human"

def check_law(state):
    return {"status": "OK" if state["law"] in ("California", "Delaware") else "ISSUE"}

def human(state):
    return {"status": "NEEDS HUMAN"}

g = StateGraph(State)
for name, fn in [("get", get_law_clause), ("read", read_law), ("check", check_law), ("human", human)]:
    g.add_node(name, fn)
g.set_entry_point("get")
g.add_edge("get", "read")
g.add_conditional_edges("read", decide, {"check": "check", "human": "human"})
g.add_edge("check", END); g.add_edge("human", END)
app = g.compile()

for cid in ["msa_04", "msa_10"]:
    print(cid, app.invoke({"cid": cid}))

3. Crash-safe steps (the idea behind Temporal)

Long jobs crash: the GPU runs out of memory, the runtime disconnects. Record each finished step. On restart, reuse recorded results instead of calling the model again. The course demo used Temporal for this; here is the same idea in 20 lines with SQLite.

07_frameworks.ipynb · cell 6
from pathlib import Path
Path("steps.sqlite").unlink(missing_ok=True)          # start clean so the timing comparison is fair
db = sqlite3.connect("steps.sqlite", check_same_thread=False)
db.execute("create table if not exists steps (key text primary key, result text)")

def durable(step_name):
    def wrap(fn):
        def inner(*args):
            key = hashlib.sha256(json.dumps([step_name, args]).encode()).hexdigest()
            row = db.execute("select result from steps where key=?", (key,)).fetchone()
            if row:
                return json.loads(row[0])                            # already done: no repeat model call
            out = fn(*args)
            db.execute("insert into steps values (?,?)", (key, json.dumps(out))); db.commit()
            return out
        return inner
    return wrap

@durable("law")
def law_step(cid):
    return app.invoke({"cid": cid})["status"]

t0 = time.time(); first = [law_step(c) for c in ids()[:6]]; t1 = time.time() - t0
t0 = time.time(); again = [law_step(c) for c in ids()[:6]]; t2 = time.time() - t0
print(f"first run {t1:.1f}s, rerun after a 'crash' {t2:.2f}s, same results: {first == again}")

# Solution 1: an agent in one line with dspy.ReAct
from lal.data import clauses
def get_clause(contract_id: str, clause: str) -> str:
    """Read one numbered clause of a contract, for example contract_id='msa_09', clause='10.1'."""
    return clauses(contract(contract_id)).get(clause, "NOT FOUND")

react = dspy.ReAct("question -> answer", tools=[get_clause], max_iters=5)
pred = react(question="Which state's law governs contract msa_09? The governing law is in clause 10.1.")
print(pred.answer, "| truth:", labels()["msa_09"]["terms"]["governing_law"])

# Solution 2: a redline node that runs only when the status is ISSUE
def redline(state):
    text = llm.invoke(f"Rewrite this clause so the governing law is Delaware. Keep everything else.\n{state['clause']}").content
    return {"redline": text}

class State2(State, total=False):
    redline: str

g2 = StateGraph(State2)
for name, fn in [("get", get_law_clause), ("read", read_law), ("check", check_law), ("human", human), ("redline", redline)]:
    g2.add_node(name, fn)
g2.set_entry_point("get")
g2.add_edge("get", "read")
g2.add_conditional_edges("read", decide, {"check": "check", "human": "human"})
g2.add_conditional_edges("check", lambda s: "redline" if s["status"] == "ISSUE" else "end", {"redline": "redline", "end": END})
g2.add_edge("redline", END); g2.add_edge("human", END)
app2 = g2.compile()
for cid in ["msa_04", "msa_10"]:
    out = app2.invoke({"cid": cid})
    print(cid, out["status"], "->", out.get("redline", "(no redline needed)"))
Traps
  • Trusting a framework's hidden prompt. Read the prompt it actually sends.
  • Picking a harness by reputation. Measure success and cost per model.
  • Metrics that return only a number. Return text ("expected X, got Y"); optimizers learn from it.

Check yourself

In the GEPA demo, what changed: the model weights or the prompt?

Only the prompt's instruction text. The small model's weights stayed the same. The big model was used only to reflect on mistakes and suggest better instructions.

Why must a Temporal workflow function avoid LLM calls?

Temporal replays the workflow code from its history to recover. Code that gives different results each time (LLM calls, I/O) breaks replay, so it goes in activities whose results are recorded.
