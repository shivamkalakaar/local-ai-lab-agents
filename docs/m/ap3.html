Enhancing Mathematical Reasoning in LLMs through Reasoning Distillation, GRPO, and Multi-agent PRM Reranking

Open in Colab
12 min readPlain-English lesson, then the deeper material

How a Stanford team made a smaller model great at hard math by copying a stronger model's reasoning, training with rewards, and picking the best of several answers.

The big idea

Hard math problems need long, careful reasoning. Big models can do it, but they use a lot of tokens (the small chunks of text a model reads and writes). Tokens cost time and money.

Abhinav Agarwal, Shree Reddy, Carlo Baronio and Shubhra Mishra tackled this in their CS329A project (Winter 2025). They stacked three ideas on top of a Qwen2.5 model:

  1. Distillation. A strong "teacher" model (DeepSeek R1) shows its full reasoning, and the smaller "student" learns to copy it. Like a junior lawyer learning by reading a senior partner's annotated memos.
  2. GRPO (Group Relative Policy Optimization). The model writes several answers to the same problem, a reward scores them, and the model is nudged toward the answers that beat the group average. Like grading a team's drafts against each other.
  3. Reranking. At test time, write several answers and let a reward model pick the best one.

The surprise was where the gain came from. Most of it came from the first step: good examples from a stronger model.

Why it matters for us

A firm can do the same with its own contract reviews. A large local model writes careful reasoning for many clauses. A smaller, faster model learns from the best of those examples.

  • Good training data matters more than clever training. Filter teacher examples with a checker, and check the steps, not just the final answer.
  • A checker that scores each answer can beat a simple vote when the right answer is rare.
  • Reward training mostly bought shorter answers here. Shorter answers mean faster reviews on the firm's own machines.

How it works, step by step

  1. Build a big, clean dataset. They gathered 387K problems. About 15% of newly generated solutions were rejected by a GPT-4o-mini judge. This is rejection sampling: generate many, keep only the good ones.

  2. Distill. Train the student on the teacher's full chain of thought (the written-out reasoning steps).

  3. Train with GRPO. The reward was 1.0 for a correct answer plus 0.2 for the right format. They set the KL penalty to 0. The KL penalty normally keeps the model close to a frozen copy of itself, the reference model. Setting it to 0 means no reference model at all, which saves a whole model's worth of memory.

  4. Rerank at test time. Several solvers write answers. A reward model picks the best.

Here is the ablation (turning parts on one at a time) on AIME'24, a hard math contest:

Stage Score
Base model 50.0%
+ distillation 72.1% (+22.1)
+ GRPO 76.7% (+4.6)
+ reranking 79.9% (+3.2)

The 32B GRPO model used 5,048 tokens per problem, against 32K for the baselines. Reward-model picking beat majority voting at every size. For example, Qwen2.5-Math-7B scored 70.0% with the reward model over 64 answers, against 43.3% by majority vote. One warning: after about 320 GRPO steps on the 7B model, answers got cut off, and they had to double the context window (how much text the model can handle at once) from 8,192 to 16,384 tokens.

A note of care: AIME'24 has only 30 problems, so 79.9% is not a score you can get on one run. The paper doesn't explain it.

Worked example

Picture the firm's teacher model reviewing a fee clause. It writes: "Step 1: 12 months × $10,000 = $120,000. Step 2: cap is $150,000, which is above the limit." The final verdict might be right, but if a step's math is wrong, we don't want the student to learn it.

Our notebook uses seeded word problems with exact answers, and a small code checker that recomputes every "a op b = c" in each step:

print(step_scores("Step 1: 12 * 7 = 84\nStep 2: 84 - 9 = 76\nStep 3: 76 / 4 = 19\nANSWER: 19"))
  • The input is a three-step solution.
  • Step 1 is right: 12 × 7 is 84. Score 1.0.
  • Step 2 is wrong: 84 − 9 is 75, not 76. Score 0.0.
  • Step 3 is right as written: 76 ÷ 4 is 19. Score 1.0.
  • The output is [1.0, 0.0, 1.0].

We use this checker twice.

First, for distillation data. The teacher (llama3.1:8b) writes 2 answers per problem. We keep only answers with the right final number and no wrong step. Among those, we keep the shortest. The result is a ready-to-train file.

Second, for reranking. The student (llama3.2:3b) writes 4 answers per test problem. A solution's score is its weakest step, the minimum. One bad step ruins the answer, just as one wrong number ruins a fee calculation. We compare five ways to choose: the first answer, a majority vote, the code checker, a model judge that names the first wrong step, and the oracle. The oracle asks "was any of the 4 right?" It is the ceiling for any picker.

An optional part trains a tiny model (SmolLM2-135M) with GRPO, using the paper's 1.0 + 0.2 reward and a KL penalty of 0.

Common mistakes

  • Spending effort on reward training first. Here distillation gave +22.1 points and GRPO gave +4.6. Get good examples first.
  • Checking only the final answer. A right answer reached through a wrong step teaches bad habits. Check every step.
  • Relying on majority vote for rare answers. If the right answer shows up once in four, a vote loses it. A step checker can still pick it.
  • Ignoring cut-off answers during training. Watch answer length. Raise the limit before truncation hurts accuracy.
  • Reading small benchmarks too precisely. With 30 problems, one question moves the score by 3.3 points.

Check your understanding

Which stage gave the biggest gain in the ablation?

Distillation, which lifted the score from 50.0% to 72.1%. GRPO and reranking added smaller gains after that.

Why score a solution by its weakest step instead of the average?

One wrong step usually ruins the answer. An average lets a long solution with one bad step beat a short correct one.

What does setting the KL penalty to 0 save?

It removes the need for a frozen reference model during training, which saves a whole model's memory.

Paper · Poster

Problem
Olympiad-level math (the AIMO prize) needs long, consistent reasoning, and models spend many tokens getting there.
Method
A 387K-problem dataset (OpenR1-Math-220K 55%, 150K newly generated 37.5%, Bespoke-Stratos-17K 7.5%; a GPT-4o-mini judge rejected about 15% of generated solutions). Chain-of-thought distillation from DeepSeek R1 into Qwen2.5 with a KL + cross-entropy loss and a falling temperature. GRPO with KL penalty beta = 0 (no reference model), reward 1.0 for correctness + 0.2 for format, DeepSpeed ZeRO-3 and colocated vLLM, scaled to 32B. Ablation: base 50.0%, distillation only 72.1% (+22.1), + GRPO 76.7% (+4.6), + reranking 79.9% (+3.2). Baselines: Qwen2.5-32B Instruct 26.7%, Qwen2.5-Math-72B 30.0% (40.0% with tool-integrated reasoning), R1-Distill-Qwen-32B 73.3%. Qwen2.5-1.5B GRPO 10.0%, 7B GRPO 16.7%; their 7B pipeline 65.2% (5,137 tokens) vs. 58.7% baseline. 2.1x faster inference. Context window had to grow from 8,192 to 16,384 tokens after about 320 GRPO steps on 7B. Reward-model selection beat majority voting at every size (e.g., Qwen2.5-Math-7B 70.0% rm@64 vs. 43.3% maj@64). Note: AIME'24 has 30 problems, and 79.9% is not a multiple of 1/30; the paper does not explain this.
Lessons
Most of the gain came from distillation (good data from a stronger model), not RL; RL then mostly bought token efficiency. Filter distillation data with a checker, including the steps, not just the final answer. A verifier that scores candidates beats majority voting when the right answer is rare. Setting the KL penalty to 0 saves a whole model's memory and worked here. Watch for truncated completions during RL.

Seeded word problems from lal.tasks. Distillation data: llama3.1:8b samples 2 rationales per problem; we keep only those with the right answer and no wrong calculation, and choose the shortest, writing a ready-to-train SFT JSONL. Reranking: llama3.2:3b writes 4 solutions per test problem; we compare first sample, majority vote, a code step-checker used as a process reward (min over steps), an LLM judge that names the first wrong step, and the pass@4 oracle. The original project

Enhancing Mathematical Reasoning in Large Language Models through Reasoning Distillation, GRPO, and Multi-agent PRM Reranking by Abhinav Agarwal, Shree Reddy, Carlo Baronio and Shubhra Mishra (Stanford CS329A, Winter 2025). Paper · Poster · code: github.com/abhinav30219/math_reasoner

Problem. Olympiad-level math (the AIMO prize) needs long, consistent reasoning, and today's models spend a lot of tokens getting there.

Method. 1. Data: 387K problems: OpenR1-Math-220K (55%), 150K newly generated (37.5%), Bespoke-Stratos-17K (7.5%). A GPT-4o-mini judge plus format checks rejected about 15% of generated solutions. 2. Distillation: DeepSeek R1 as teacher, Qwen2.5 as student, loss L = α·KL(teacher‖student) + (1−α)·CE, with a temperature that starts high and drops, and extra weight on reasoning tokens. 3. GRPO (Shao et al. 2024, DeepSeekMath): sample a group of answers per problem and use the group's average reward as the baseline, so no separate value network is needed. Their key choice: KL penalty β = 0, so the reference model can be dropped from memory. Reward = 1.0 for a correct answer + 0.2 for the right format. 4. Multi-agent "PRM" reranking: several solvers with different settings, self-verification, then a reward model ranks the candidates and the best one is kept. (In this paper PRM stands for Preference Reward Model.)

Key results (as reported, AIME'24). - 32B model after GRPO: 76.7% with 5,048 tokens per problem, vs. 32K tokens for baselines (a "6.3× reduction"). - With multi-agent reranking over 4 inference passes: 79.9%. - Ablation: base model 50.0% → distillation only 72.1% (+22.1) → + GRPO 76.7% (+4.6) → + reranking 79.9% (+3.2). - Baselines: Qwen2.5-32B Instruct 26.7%, Qwen2.5-Math-72B 30.0% (40.0% with tool-integrated reasoning), R1-Distill-Qwen-32B 73.3%. - Scale: Qwen2.5-1.5B GRPO 10.0%, 7B GRPO 16.7%. Their 7B pipeline: 65.2% with 5,137 tokens vs. 58.7% baseline. - 2.1× faster inference. After about 320 GRPO steps on 7B, truncated answers hurt accuracy until they raised the context window from 8,192 to 16,384 tokens. - Reward-model selection beat majority voting at every size (for example Qwen2.5-Math-7B: 70.0% rm@64 vs. 43.3% maj@64).

Read with care (our note). AIME'24 has 30 problems, so scores move in steps of 3.3 points. 79.9% is not a multiple of 1/30; it may be an average over runs, but the paper doesn't say. Also, some baselines (such as R1-Distill) are known to be reasoning models given a 32K budget, so the token comparison mixes model types. The poster adds a neat fact: with β = 0, one gradient step per batch and normalized advantages, the GRPO loss is always 0 while the gradient is not.

Our mini version. This repo does not use Qwen or DeepSeek models, so: llama3.1:8b is the teacher, llama3.2:3b is the student at test time, and SmolLM2-135M-Instruct is the model we train with GRPO (optional). Problems come from lal.tasks (generated with a seed), so every answer is exact.

A step checker made of code: it recomputes every a op b = c it finds in a step. We use it twice: to filter teacher data, and later as a process reward for reranking.

ap3_math_reasoning.ipynb · cell 4
def safe_eval(expr):
    node = ast.parse(expr.replace("×", "*").replace("÷", "/").replace("−", "-").strip(), mode="eval")
    def ev(n):
        if isinstance(n, ast.Expression): return ev(n.body)
        if isinstance(n, ast.Constant) and isinstance(n.value, (int, float)): return float(n.value)
        if isinstance(n, ast.UnaryOp) and isinstance(n.op, ast.USub): return -ev(n.operand)
        if isinstance(n, ast.BinOp) and isinstance(n.op, (ast.Add, ast.Sub, ast.Mult, ast.Div)):
            a, b = ev(n.left), ev(n.right)
            return {ast.Add: a + b, ast.Sub: a - b, ast.Mult: a * b, ast.Div: a / b if b else float("nan")}[type(n.op)]
        raise ValueError("unsupported")
    return ev(node)

CALC = re.compile(r"([\d\.\s\+\-\*/×÷\(\)]*\d[\d\.\s\+\-\*/×÷\(\)]*)=\s*(-?\d+(?:\.\d+)?)")

def step_scores(solution):
    """One score per step: 1.0 if every calculation in it is right, 0.0 if any is wrong."""
    scores = []
    for line in (solution or "").replace(",", "").replace("$", "").splitlines():
        if not re.match(r"\s*\**step", line, re.I):
            continue
        ok = True
        for left, right in CALC.findall(line):
            if not re.search(r"[\+\-\*/×÷]", left.strip().lstrip("-")):
                continue                                   # "x = 5" is not a calculation
            try:
                ok &= abs(safe_eval(left) - float(right)) < 0.01
            except Exception:
                pass                                       # can't parse: don't punish
        scores.append(1.0 if ok else 0.0)
    return scores

print(step_scores("Step 1: 12 * 7 = 84\nStep 2: 84 - 9 = 76\nStep 3: 76 / 4 = 19\nANSWER: 19"))   # step 2 is wrong

2. Stage 1: reasoning distillation data

The real recipe trains the student on the teacher's full reasoning. The data step is what we can do here: sample 2 rationales per problem from the teacher, keep only the correct ones (rejection sampling, like the paper's ~15% reject rate). "Correct" means the right final answer and no wrong calculation in any step: a right answer reached through a wrong step teaches the student bad habits. Among the correct ones keep the shortest. That last step pushes toward the token efficiency the paper reports. The output is a ready-to-train SFT file (20 calls).

ap3_math_reasoning.ipynb · cell 5
STEP_PROMPT = ("Solve the problem step by step. Put each step on its own line as 'Step k: ...' and write every "
               "calculation as 'a op b = c'. End with a line 'ANSWER: <integer>'.\n\nProblem: {q}")

def sample(q, model, temperature):
    try:
        return ask(STEP_PROMPT.format(q=q), model_name=model, temperature=temperature, max_tokens=500)
    except Exception as e:
        print("call failed:", e); return ""

jobs = [(q, a) for q, a in TRAIN for _ in range(2)]
with ThreadPoolExecutor(2) as ex:
    teacher_out = list(ex.map(lambda qa: sample(qa[0], TEACHER, 0.7), jobs))

by_q = {}
for (q, a), out in zip(jobs, teacher_out):
    by_q.setdefault(q, []).append((extract_int(out) == a, out))
sft, lucky = [], 0
for q, cands in by_q.items():
    # Right answer AND no wrong calculation in any step (the step checker is defined in section 3).
    lucky += sum(ok and 0.0 in step_scores(o) for ok, o in cands)
    good = sorted((o for ok, o in cands if ok and 0.0 not in step_scores(o)), key=len)
    if good:
        sft.append({"prompt": [{"role": "user", "content": STEP_PROMPT.format(q=q)}],
                    "completion": [{"role": "assistant", "content": good[0].strip()}]})
n_ok = sum(ok for c in by_q.values() for ok, _ in c)
avg_all = sum(len(o) for o in teacher_out) / max(len(teacher_out), 1)
avg_kept = sum(len(r["completion"][0]["content"]) for r in sft) / max(len(sft), 1)
print(f"teacher correct: {n_ok}/{len(jobs)} (rejected {1 - n_ok / len(jobs):.0%})")
print(f"right answer but a wrong step inside (also rejected): {lucky}")
print(f"problems with at least one correct rationale: {len(sft)}/{len(TRAIN)}")
print(f"avg characters: all samples {avg_all:.0f} → kept (shortest correct) {avg_kept:.0f}")
DATA = Path("cs329a_projects/ap3_distill.jsonl"); DATA.parent.mkdir(exist_ok=True)
DATA.write_text("\n".join(json.dumps(r) for r in sft))
print("wrote", DATA, "\n\nexample:\n", sft[0]["completion"][0]["content"][:400] if sft else "(none)")

3. Stage 3: sample N answers, then rerank with step scores

The student (llama3.2:3b) writes N = 4 solutions per test problem (24 calls). We compare five ways to pick one: - first sample: what a single call gives you; - majority vote (self-consistency, Wang et al. 2023); - code step-checker: a process reward made by code. Every a op b = c in a step is recomputed; a step scores 1 if all its calculations are right. A solution's score is its weakest step (min), as in Lightman et al. 2023, Let's Verify Step by Step; - LLM judge: the 8B model reads all 4 solutions and names the first wrong step in each (1 call per problem); - oracle (pass@4): is any of the 4 right? This is the ceiling for any reranker.

ap3_math_reasoning.ipynb · cell 6
N = 4
with ThreadPoolExecutor(2) as ex:
    cand = list(ex.map(lambda qi: sample(TEST[qi[0]][0], STUDENT, 0.8), [(i, j) for i in range(len(TEST)) for j in range(N)]))
CANDS = [cand[i * N:(i + 1) * N] for i in range(len(TEST))]
ap3_math_reasoning.ipynb · cell 7
class Verdict(BaseModel):
    solution: int
    first_wrong_step: int = Field(description="number of the first wrong step, or 0 if all steps are right")

class Verdicts(BaseModel):
    verdicts: List[Verdict]

def llm_judge(q, sols):
    text = "\n\n".join(f"=== Solution {i + 1} ===\n{s[:1200]}" for i, s in enumerate(sols))
    try:
        v = structured(f"Problem: {q}\n\n{text}\n\nCheck every step of every solution. For each solution, give the "
                       "number of the first wrong step (0 if all steps are right).", Verdicts, model_name=TEACHER, max_tokens=400)
        got = {x.solution: x.first_wrong_step for x in v.verdicts}
    except Exception:
        got = {}
    return [1.0 if got.get(i + 1, 1) == 0 else 0.0 for i in range(len(sols))]

with ThreadPoolExecutor(2) as ex:
    JUDGE = list(ex.map(lambda i: llm_judge(TEST[i][0], CANDS[i]), range(len(TEST))))

def pick(answers, scores):
    """Highest score wins; ties go to the most common answer among the tied."""
    best = max(scores)
    tied = [a for a, s in zip(answers, scores) if s == best and a is not None]
    return Counter(tied).most_common(1)[0][0] if tied else answers[0]

def evaluate(cands, judge, agg=min):
    res = Counter()
    for (q, gold), sols, js in zip(TEST, cands, judge):
        ans = [extract_int(s) for s in sols]
        prm = [agg(step_scores(s)) if step_scores(s) else 0.5 for s in sols]
        votes = Counter(a for a in ans if a is not None)
        res["first sample"] += ans[0] == gold
        res["majority vote"] += (votes.most_common(1)[0][0] if votes else None) == gold
        res["code step-checker"] += pick(ans, prm) == gold
        res["LLM judge"] += pick(ans, js) == gold
        res["oracle (pass@N)"] += gold in ans
    return {k: v / len(TEST) for k, v in res.items()}

ACC = evaluate(CANDS, JUDGE)
for k, v in ACC.items():
    print(f"{k:18s} {v:.0%}")
correct = [sum(extract_int(s) == g for s in sols) for (q, g), sols in zip(TEST, CANDS)]
print("unbiased pass@1 over all samples:", f"{sum(pass_at_k(N, c, 1) for c in correct) / len(TEST):.0%}")

What to notice. The gap between first sample and oracle is the room a reranker has. Majority vote needs the right answer to be common; a step checker can rescue a right answer that appears only once. The paper's reranker added +3.2 points on top of a much stronger model; on easy problems with a weak model, the gap here can be bigger.

4. Stage 2 (optional, RUN_LONG): GRPO on a tiny model

GRPO samples a group of answers per prompt (here 8), scores them, and pushes up the ones above the group average. We use the paper's reward weights (1.0 correct + 0.2 format) and its β = 0 (no KL penalty, no reference model). The task is easy on purpose (two-number sums) so a 135M model can visibly learn in a few minutes. The T4 has no bf16, so we train in fp32. TRL API checked against the current GRPOTrainer docs.

ap3_math_reasoning.ipynb · cell 8
SMALL = "HuggingFaceTB/SmolLM2-135M-Instruct"
grng = random.Random(7)
def sum_prompt():
    a, b = grng.randint(10, 99), grng.randint(10, 99)
    return {"prompt": [{"role": "user", "content": f"What is {a} + {b}? Reply with only the number inside <answer></answer>."}],
            "answer": str(a + b)}

def _text(c):
    return c[0]["content"] if isinstance(c, list) else str(c)

def correctness_reward(completions, answer, **kwargs):
    out = []
    for c, a in zip(completions, answer):
        m = re.search(r"<answer>\s*(-?\d+)\s*</answer>", _text(c))
        out.append(1.0 if m and m.group(1) == a else 0.0)
    return out

def format_reward(completions, **kwargs):
    return [0.2 if re.search(r"<answer>.*?</answer>", _text(c), re.S) else 0.0 for c in completions]

print(correctness_reward([[{"content": "<answer>42</answer>"}]], ["42"]), format_reward(["<answer>x</answer>"]))

GRPO_LOG = {}
if RUN_LONG:
    import torch
    from datasets import Dataset
    from transformers import AutoModelForCausalLM, AutoTokenizer
    from trl import GRPOConfig, GRPOTrainer

    train_ds = Dataset.from_list([sum_prompt() for _ in range(400)])
    eval_rows = [sum_prompt() for _ in range(40)]
    tok = AutoTokenizer.from_pretrained(SMALL); tok.padding_side = "left"

    def mean_reward(model):
        model.eval(); total = 0.0
        for r in eval_rows:
            text = tok.apply_chat_template(r["prompt"], tokenize=False, add_generation_prompt=True)
            ids = tok(text, return_tensors="pt").to(model.device)
            with torch.no_grad():
                out = model.generate(**ids, max_new_tokens=32, do_sample=False, pad_token_id=tok.eos_token_id)
            comp = tok.decode(out[0][ids["input_ids"].shape[1]:], skip_special_tokens=True)
            total += correctness_reward([comp], [r["answer"]])[0] + format_reward([comp])[0]
        return total / len(eval_rows)
