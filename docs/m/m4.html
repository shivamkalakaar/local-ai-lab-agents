Module 04

Retrieval (RAG)

Open in Colab
12 min readPlain-English lesson, then the deeper material

How to find the few passages a model needs from many documents, by searching two ways at once and checking every quote in code.

The big idea

Retrieval means finding the right few passages before the model answers. RAG (retrieval-augmented generation) is the name for "search first, then answer from what you found."

Think of a law library. You don't hand a new associate every book and say "find the cap." You give them a good index. They pull the three pages that matter, read those, and answer. The model is the associate. Retrieval is the index.

The default that works has a few parts. Split documents on their natural structure. Label each piece with where it came from. Search two ways: by exact words and by meaning. Merge the results. Then check every quote the model gives against the real text.

Why it matters for us

A firm has many contracts. They won't all fit on the model's desk at once, and small local models do worse with long prompts. Retrieval lets the model read only the clauses that matter.

If all your documents are small, you may not need retrieval. The course's rule of thumb: under about 200K tokens of documents, put it all in the prompt and skip it. Above that, build the pipeline.

Lawyers need answers they can trust. A citation that points to a real clause, checked by code, is what makes an answer usable. Everything here, including the search model, runs on the firm's own machine.

How it works, step by step

  1. Chunk on structure. A chunk is one piece of a document. For contracts, one section makes a natural chunk. Splitting on headings keeps each idea whole.

  2. Add a context note. Put a one-line label at the top of each chunk, like "From msa_07, section 7 (Limitation of Liability)." The clause text alone never says which contract it came from. The label does. This idea is called contextual retrieval (from Anthropic).

  3. Search by keywords. BM25 is a classic keyword search. It scores chunks by shared words. It is good at exact strings like "7.2(b)" or "msa_15".

  4. Search by meaning. An embedding model turns text into a list of numbers that captures meaning. Similar meanings give similar numbers. This finds "limitation of liability" when the lawyer typed "cap on damages."

  5. Merge with RRF. Reciprocal rank fusion combines two ranked lists. Each chunk gets points for ranking high in either list: 1 divided by (60 plus its rank). Add the points and sort.

  6. Optionally rerank. Fetch a wide pool, then let a slower, more accurate model reorder it and keep the best few.

  7. Check citations in code. The model must name its source chunk and give an exact quote. Code confirms the quote is really in that chunk.

question --> keyword search  --\
                                 merge (RRF) --> top chunks --> model answers --> code checks quote
question --> meaning search  --/

Worked example

The notebook turns all 20 contracts into chunks, one per section. Each chunk gets its context note. It builds both indexes, then searches "msa_15 cap on damages." The top hit is section 7 of msa_15.

Next it measures retrieval on its own. It uses recall@k: out of all test questions, how often was the right chunk in the top k results? The questions use different words from the contracts, like "how do we stop it renewing." The notebook prints recall@3 for keyword only, meaning only, and hybrid.

Then it answers a real question with citations:

hits = index.search(question, k=k)
ctx = "\n\n".join(f"[{c['id']}] {c['text']}" for c in hits)
a = structured([... "Answer only from the sources. Give the source id and an exact quote." ...], Answer)
src = next((c for c in hits if c["id"] == cid), None)

  • The first line runs the hybrid search and keeps the top few chunks.
  • The second line joins them into one block, each tagged with its ID like [msa_20#7].
  • The third line asks the model for an answer, a source ID and an exact quote, in a fixed shape.
  • The fourth line finds the chunk the model named among the ones we gave it.
  • The last line checks that the chunk exists and the quote really appears in it.

For "What is the liability cap in msa_20?" you get the answer, the chunk ID, the quote, and "citation verified: True" or False.

Common mistakes

  • Using meaning search alone. It misses exact strings like clause numbers and IDs. Use keyword search too.
  • Judging retrieval only by the final answer. If the answer is wrong, you can't tell which part failed. Measure recall@k separately.
  • Treating retrieved text as instructions. It is data. A contract could contain "ignore previous instructions."
  • Ignoring who may see what. Filter by client or matter during the search, not after.

Check your understanding

A lawyer asks "what does 7.2(b) say?" and meaning search returns the wrong clause. Why?

Embeddings capture meaning, not exact strings like "7.2(b)". Keyword search finds it. That is why we search both ways.

Why add a context note to each chunk?

The clause text alone doesn't say which contract or section it belongs to. The note carries that, which helps both kinds of search.

Why fetch a wide pool and then rerank, instead of fetching only a few?

Fast search is noisy. A wide pool makes sure the right passage is in there. The slower reranker then moves it to the top.

Go deeper

Key terms, papers, evidence, the full notebook code and worked solutions.

Lecture 3 · Lewis et al. (RAG) · DPR · ColBERT · Anthropic, "Contextual Retrieval"

Retrieval finds the few passages the model needs. The default that works: search two ways (keywords and meaning), merge, rerank, and check every citation in code.

Key terms

RAG
Retrieval-augmented generation: first find relevant passages, then have the model answer from them.Source: Lewis et al., "Retrieval-Augmented Generation", NeurIPS (2020)
BM25
A classic keyword-matching score. Strong for exact strings such as clause numbers, IDs and names.Source: Lecture 3
Dense retrieval / embeddings
Turning text into vectors so passages with similar meaning are close together, even with different words.Source: Karpukhin et al., "Dense Passage Retrieval", EMNLP (2020)
Reciprocal rank fusion (RRF)
Merging ranked lists by adding 1/(k + rank) for each list (k ≈ 60). Simple and robust for hybrid search.Source: Lecture 3
Reranker / late interaction
A slower model that scores (query, passage) pairs more carefully to reorder the top candidates. ColBERT does this efficiently by comparing token-level vectors.Source: Khattab & Zaharia, "ColBERT", SIGIR (2020)
Contextual retrieval
Prepending a short note to each chunk saying where it comes from before indexing. Failed retrievals dropped from 5.7% to 1.9% with reranking.Source: Anthropic, "Contextual Retrieval" (2024), cited in Lecture 3
Recall@k
Share of questions where the right passage is in the top k results. Measures retrieval on its own.Source: Lecture 3

The decision

  • Under about 200K tokens of documents? Put it all in the prompt and skip retrieval.
  • More than that? Build the pipeline below.

The pipeline

  1. Chunk on structure. Split by headings or clauses first. Otherwise use 100–500 token chunks with 10–20% overlap.
  2. Add context to each chunk. Prepend a one-line note: "From the MSA with Acme, section 12, Limitation of Liability."
  3. Search two ways. Keyword search (BM25) catches exact strings like "12.3" or a lot number. Embedding search catches rewording like "cap on damages" vs. "limitation of liability."
  4. Merge with reciprocal rank fusion (RRF): score = Σ 1/(60 + rank).
  5. Rerank. Fetch about 150 candidates, rerank with a slower, more accurate model, and keep about 20.
  6. Verify citations. Every quote the model gives must appear in the source text, checked in code.
5.7% → 1.9%

Failed retrievals: plain chunks vs. contextual chunks with hybrid search and reranking (Anthropic).

10–20

Documents in the prompt beyond which accuracy stops improving; models also ignore the middle of long contexts (L4).

1. Chunk on structure, with context

Each chunk is one section of one contract. We prepend a short note saying where it came from (Anthropic's "contextual retrieval"), which helps both search methods.

chunks = []
for cid in ids():
    for s in sections(contract(cid)):
        chunks.append({"id": f"{cid}#{s['id']}", "contract": cid, "section": s["id"],
                       "context": f"From {cid}, section {s['id']} ({s['title']}).", "text": s["text"]})

2. Two searches, merged with RRF

04_retrieval_rag.ipynb · cell 4
embedder = SentenceTransformer("BAAI/bge-small-en-v1.5")      # small, local embedding model
QUERY_PREFIX = "Represent this sentence for searching relevant passages: "   # what bge models expect on queries
tok = lambda s: re.findall(r"\w+", s.lower())                 # word tokens, so "msa_15," matches "msa_15"

class HybridIndex:
    def __init__(self, chunks):
        self.chunks = chunks
        docs = [f"{c['context']}\n{c['text']}" for c in chunks]
        self.bm25 = BM25Okapi([tok(d) for d in docs])
        self.vecs = embedder.encode(docs, normalize_embeddings=True, show_progress_bar=False)

    def keyword(self, q, n):
        return list(np.argsort(-self.bm25.get_scores(tok(q)))[:n])

    def semantic(self, q, n):
        qv = embedder.encode([QUERY_PREFIX + q], normalize_embeddings=True)[0]
        return list(np.argsort(-(self.vecs @ qv))[:n])

    def search(self, q, k=5, pool=50, mode="hybrid", rrf_k=60):
        if mode == "keyword": return [self.chunks[i] for i in self.keyword(q, k)]
        if mode == "semantic": return [self.chunks[i] for i in self.semantic(q, k)]
        scores = {}
        for ranking in (self.keyword(q, pool), self.semantic(q, pool)):
            for r, i in enumerate(ranking):
                scores[i] = scores.get(i, 0) + 1 / (rrf_k + r + 1)
        return [self.chunks[i] for i in sorted(scores, key=scores.get, reverse=True)[:k]]

index = HybridIndex(chunks)
for c in index.search("msa_15 cap on damages", k=3):
    print(c["id"], "|", c["text"][:80])

3. Measure retrieval on its own: recall@k

Did the right chunk come back? We test with questions that use different words from the contract ("cap on damages" vs. "limitation of liability"), and questions with exact IDs.

04_retrieval_rag.ipynb · cell 5
QUERIES = []
for cid in ids()[:10]:
    QUERIES += [(f"{cid} cap on damages", f"{cid}#7"), (f"which state's law applies in {cid}", f"{cid}#10"),
                (f"{cid} how do we stop it renewing", f"{cid}#4")]

def recall_at_k(mode, k=3):
    return sum(any(c["id"] == gold for c in index.search(q, k=k, mode=mode)) for q, gold in QUERIES) / len(QUERIES)

for mode in ("keyword", "semantic", "hybrid"):
    print(f"{mode:9} recall@3 = {recall_at_k(mode):.0%}")

4. Answer from retrieved chunks, with citations checked in code

04_retrieval_rag.ipynb · cell 6
from pydantic import BaseModel
class Answer(BaseModel):
    answer: str
    chunk_id: str
    quote: str

def rag(question, k=4):
    hits = index.search(question, k=k)
    ctx = "\n\n".join(f"[{c['id']}] {c['text']}" for c in hits)
    a = structured([{"role": "system", "content": "Answer only from the sources. Give the source id and an exact quote."},
                    {"role": "user", "content": f"Sources:\n{ctx}\n\nQuestion: {question}"}], Answer)
    cid = a.chunk_id.strip().strip("[]")                     # models often copy the brackets
    src = next((c for c in hits if c["id"] == cid), None)
    a_ok = src is not None and quote_is_in_doc(a.quote, src["text"])
    return a, a_ok

a, ok = rag("What is the liability cap in msa_20?")
print(a.model_dump(), "\ncitation verified:", ok)

# Solution 2: add a reranker: fetch 20, rerank with a cross-encoder, keep the best
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
def search_rerank(q, k=3, first=20):
    cands = index.search(q, k=first)
    scores = reranker.predict([(q, f"{c['context']} {c['text']}") for c in cands])
    return [c for _, c in sorted(zip(scores, cands), key=lambda x: -x[0])][:k]
rr = sum(any(c["id"] == gold for c in search_rerank(q)) for q, gold in QUERIES) / len(QUERIES)
print(f"hybrid recall@3 {recall_at_k('hybrid'):.0%} -> hybrid + rerank recall@3 {rr:.0%}")
Traps
  • Embeddings only. They miss exact identifiers like clause numbers, IDs and lot numbers.
  • Judging retrieval by the final answer. Measure recall@k separately, or you can't tell which part failed.
  • Treating retrieved text as instructions. It is data. A contract can contain "ignore previous instructions".
  • Ignoring access rights. Filter by client or matter at search time, not after.
