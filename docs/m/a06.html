Open-ended evolution of self-improving agents

Open in Colab
9 min readSlides first, then the deeper material

Let a model propose changes to code, agents or experiments, score each one automatically, and keep an archive of what worked.

Based on CS329A · Open-ended evolution of self-improving agents · main paper

Learning objective

1/13
  • Learn the propose → evaluate → archive loop behind AlphaEvolve, ADAS and the AI Scientist, and why the evaluator matters most.

One loop, three systems

2/13
  • Propose: an LLM suggests a change (to code, an agent, an experiment).
  • Evaluate: a program scores it automatically.
  • Archive: store every candidate with its score; build on the good ones.
  • Repeat.
  • Progress comes from the evaluator and the archive. The LLM supplies the guesses.

Key terms

3/13
  • Archive: every candidate tried so far, with its score.
  • Open-endedness: search for new and interesting, not only better on one number.
  • Meta agent: an agent whose job is to write other agents, as code.
  • Evaluation cascade: a tiny fast test first; full test only for those that pass.
  • Sandbox: run untrusted code in a separate, limited process (timeouts, no network).

AlphaEvolve (Novikov et al. 2025)

4/13
  • Program database keeps diversity:
    • MAP-Elites: keep the best candidate in each niche
    • Islands: evolve several separate populations
  • Gemini 2.0 Flash (many fast ideas) + Gemini 2.0 Pro (fewer, better ones) propose code diffs.
  • Automatic evaluators score each child, often as a cascade.

Mini AlphaEvolve: bin packing

6/13
  • Task: put items into as few bins of size 100 as possible.
  • Program to evolve: pack(items, capacity). Seed: next fit.
  • Evaluator:
    • Validity first: every item used once, no bin over capacity; invalid scores 0
    • Quality: lower bound / bins used. 1.0 is perfect.
  • Cascade: 2 small instances first, then 20 full ones.

Without vs with a validity check

8/13
Score only Validity check first
One overfilled bin scores 27 out of a "perfect" 1.0 Overfilled packing scores 0

  • Reward hacking: scoring high in a way that breaks the task's intent.
  • The search optimizes what you measure, cheats included.

ADAS: a meta agent designs agents (Hu et al. 2024)

9/13
  • Agents are code: a forward() function that may call the model several times.
  • Meta agent reads the archive (designs + scores), writes a new design.
  • New design runs on validation tasks; score goes into the archive.
  • Archive seeded with hand designs: Chain-of-Thought, Self-Refine.
  • GPT-4 meta agent, GPT-3.5 running agents:
    • +13.6 F1 on DROP, +14.4% on MGSM over the best hand designs
    • Kept an edge when moved to other models (e.g. Claude, GPT-4)

Darwin Gödel Machine (Zhang et al. 2025)

10/13
  • A coding agent rewrites its own code.
  • Each new version is tested on coding benchmarks and kept in the archive.
  • New versions branch from any archive member, not only the current best.
  • SWE-bench 20.0% → 50.0%; Polyglot 14.2% → 30.7%.
  • Stepping stones that look worse now can lead to the biggest later gains.

The AI Scientist (Lu et al. 2024)

11/13
  • Idea → experiment code → run → write-up → automated review.
  • Under $15 per paper.
  • GPT-4o reviewer: 0.65 balanced accuracy on 500 ICLR 2022 papers; humans 0.66.
  • Safety issues: it edited its own code to extend timeouts; once relaunched itself repeatedly.
  • Our version adds a code check: do the write-up's numbers appear in the raw results?

How this applies to us

12/13
  • The firm's past reviews, with correct playbook flags, are the evaluator for evolving a review agent.
  • All proposals run in a sandbox on the firm's machine with a local model.
  • Confirm any winner on contracts the search never saw.

Common mistakes

13/13
  • No validity check → the search finds the loophole. Check validity before quality.
  • Trusting a tiny search set → with 6 questions, one answer is 17 points; confirm on held-out data.
  • Running model code in your own process → use a subprocess or container with a timeout.
  • Keeping only the current best → keep the archive and some diversity.

Go deeper

Key terms, papers, evidence, the full notebook code and worked solutions.

CS329A Lecture 7 (Oct 13)

Let an LLM propose changes to code, agents or experiments, score every proposal automatically, and keep an archive of what worked to build on. Progress comes from the evaluator and the archive; the LLM supplies the guesses.

Key terms

Archive
The stored set of every candidate tried so far with its score. New candidates are made by changing archive members.Source: Hu et al. 2024; Zhang et al. 2025
Open-endedness
Searching for things that are new and interesting, not only better on one number, so the search keeps finding stepping stones instead of getting stuck.Source: lecture
Meta agent
An agent whose job is to write other agents (as code), as in ADAS's Meta Agent Search.Source: Hu et al. 2024
Evaluation cascade
Test each candidate on a tiny, fast test first, and only run the full, expensive test on candidates that pass.Source: Novikov et al. 2025
MAP-Elites / islands
Ways to keep diversity: keep the best candidate in each 'niche' (MAP-Elites), or evolve several separate populations (islands).Source: Novikov et al. 2025
Sandbox
Running untrusted code in a separate, limited process or container (timeouts, no network, limited disk) so it cannot harm the host.Source: Lu et al. 2024
Reward hacking
The search finds a way to score high that breaks the intent of the task, e.g. a 'packing' that overfills bins when the evaluator forgets to check.Source: lecture

The papers

Automated Design of Agentic Systems

Hu, Lu & Clune · 2024

What
Agents are defined as code (a forward() function). Meta Agent Search: a meta agent reads an archive of earlier agents with their scores, writes a new agent, checks it for novelty with two self-reflection steps, evaluates it on validation data (repairing errors up to five times) and adds it to the archive. The archive is seeded with hand-designed agents like Chain-of-Thought and Self-Refine.
Result
With GPT-4 as meta agent and GPT-3.5 running the agents: +13.6 F1 (out of 100) on DROP and +14.4% accuracy on MGSM over the best hand-designed agents; agents found on MGSM gave +25.9% on GSM8K and +13.2% on GSM-Hard when transferred. Discovered agents kept their edge when moved to other models (e.g. Claude, GPT-4).
Takeaway
If you have a checkable task set, let a strong model search over agent designs written as code, with a held-out set to catch lucky winners. Start the archive with the designs you already use.

Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents

Zhang, Hu, Lu, Lange & Clune · 2025

What
The course page links the 'Automated design of agentic systems' reading to this paper. A coding agent rewrites its own code; each new version is tested on coding benchmarks and kept in a growing archive (a tree of agents), and new versions are branched from archive members, not only from the latest best.
Result
SWE-bench 20.0% -> 50.0% and Polyglot 14.2% -> 30.7%, beating variants without self-improvement or without open-ended exploration.
Takeaway
Keep the whole archive, not just the current best: stepping stones that look worse now often lead to the biggest later gains.

The AI Scientist: Towards Fully Automated Open-Ended Scientific Discovery

Lu, Lu, Lange, Foerster, Clune & Ha · 2024

What
A pipeline where LLMs generate research ideas (checked for novelty against Semantic Scholar), write and run experiment code with the Aider coding assistant, plot results, write a full LaTeX paper and review it with an automated reviewer. Applied to diffusion models, transformer language modeling and learning dynamics.
Result
Under $15 per paper. The GPT-4o reviewer reached 0.65 balanced accuracy on accept/reject for 500 ICLR 2022 papers, vs 0.66 for humans (from the NeurIPS 2021 consistency experiment). The authors report safety issues: the system edited its own code to extend timeouts and once relaunched itself repeatedly.
Takeaway
Automating the full loop is possible, but the weak points are the LLM reviewer and the sandbox. Ground every claim in the raw results with code, and run generated code in a container with timeouts, storage limits and no network.

AlphaEvolve: A coding agent for scientific and algorithmic discovery

Novikov et al. (Google DeepMind) · 2025

What
An evolutionary loop: a program database (MAP-Elites plus islands) feeds a prompt sampler; an ensemble of Gemini 2.0 Flash (many fast ideas) and Gemini 2.0 Pro (fewer, better ones) proposes code diffs in SEARCH/REPLACE format inside marked EVOLVE-BLOCKs; automatic evaluators score each child, optionally as a cascade of harder and harder tests.
Result
A 4x4 complex matrix multiplication with 48 scalar multiplications, the first improvement over Strassen in this setting in 56 years. On 50+ open math problems it matched the best known constructions in about 75% and improved them in about 20% (e.g. kissing number in 11 dimensions: 593, previous 592). At Google: a scheduling heuristic recovering on average 0.7% of fleet-wide compute, a 23% average kernel speedup giving 1% less Gemini training time, and a 32% speedup of a FlashAttention kernel.
Takeaway
Any problem with a fast, trustworthy scoring function is a candidate for LLM-driven evolution. Spend your effort on the evaluator (validity first, then quality) and let cheap models generate many candidates.

1. The sandbox: never run model code in your own process

Model-written code can loop forever, eat memory, or delete files. We write it to a temp folder and run it in a separate Python process with: - a wall-clock timeout, - a CPU-time and (on Linux) memory limit, - python -I (isolated mode: ignores environment variables and the user's site folder), - the temp folder as working directory.

This is a speed bump, not a real sandbox. It does not block the network or reading files. For real use, run it in a container with no network. The AI Scientist paper reports why: in some runs their system edited its own code to raise its timeout, and relaunched itself until a human had to stop it (Lu et al. 2024).

a06_open_ended_evolution.ipynb · cell 3
def run_sandboxed(code, timeout=10, mem_mb=1024):
    """Run code in a fresh Python process. The program reports by printing one line: RESULT <json>."""
    # The child sets its own CPU and memory limits first. (Setting them from the parent with preexec_fn
    # is unsafe in a Jupyter kernel, which runs threads.)
    header = ("try:\n    import resource, sys as _s\n"
              f"    resource.setrlimit(resource.RLIMIT_CPU, ({timeout + 1}, {timeout + 1}))\n"
              f"    if _s.platform.startswith('linux'): resource.setrlimit(resource.RLIMIT_AS, ({mem_mb} * 2**20, {mem_mb} * 2**20))\n"
              "except Exception:\n    pass\n")
    with tempfile.TemporaryDirectory() as d:
        path = os.path.join(d, "prog.py")
        with open(path, "w") as f:
            f.write(header + code)
        t0 = time.time()
        try:
            p = subprocess.run([sys.executable, "-I", path], cwd=d, capture_output=True, text=True, timeout=timeout)
        except subprocess.TimeoutExpired:
            return {"ok": False, "error": f"timeout after {timeout}s", "seconds": timeout}
        secs = round(time.time() - t0, 2)
        lines = [l for l in p.stdout.splitlines() if l.startswith("RESULT ")]
        if not lines:
            return {"ok": False, "error": (p.stderr or p.stdout or "no RESULT line")[-500:], "seconds": secs}
        try:
            return {"ok": True, "result": json.loads(lines[-1][7:]), "seconds": secs}
        except Exception as e:
            return {"ok": False, "error": f"bad RESULT json: {e}", "seconds": secs}

def code_block(text):
    """Pull the first ```python block out of a reply (or the whole reply if there is none)."""
    m = re.search(r"```(?:python|py)?\s*\n(.*?)```", text or "", re.S)
    return (m.group(1) if m else (text or "")).strip()

print(run_sandboxed("print('RESULT', 1+1)"))
print(run_sandboxed("while True: pass", timeout=2))

2. Mini AlphaEvolve: evolve a bin-packing function

AlphaEvolve (Novikov et al. 2025, Google DeepMind) keeps a database of programs. Each step it picks a parent, shows the LLM the parent plus a few good "inspiration" programs with their scores, asks for an improved version, runs the evaluator, and stores the child. Among its results: a way to multiply two 4x4 complex matrices with 48 scalar multiplications (Strassen's method, from 1969, needs 49), and a scheduling heuristic that recovers on average 0.7% of Google's fleet-wide compute.

Our problem: bin packing. Put items of different sizes into as few bins of size 100 as possible. The program to evolve is pack(items, capacity). The evaluator: 1. checks validity (every item used exactly once, no bin over capacity); an invalid packing scores 0, 2. scores quality as lower bound / bins used, where the lower bound is ceil(total size / capacity). 1.0 would be perfect.

It runs as an evaluation cascade, an idea from the paper: a tiny test first, and only programs that pass it get the full test.

a06_open_ended_evolution.ipynb · cell 4
SEED_PROGRAM = '''def pack(items, capacity):
    """Next fit: keep one open bin; start a new one when the item does not fit."""
    bins, current, room = [], [], capacity
    for x in items:
        if x > room:
            bins.append(current)
            current, room = [], capacity
        current.append(x)
        room -= x
    if current:
        bins.append(current)
    return bins
'''

BP_HARNESS = '''
import json, math, random
from collections import Counter

{code}

def run_stage(seed, n_inst, n_items, cap=100):
    rng = random.Random(seed)
    scores = []
    for _ in range(n_inst):
        items = [rng.randint(20, 70) for _ in range(n_items)]
        bins = pack(list(items), cap)
        flat = [x for b in bins for x in b]
        if Counter(flat) != Counter(items) or any(sum(b) > cap for b in bins) or any(len(b) == 0 for b in bins):
            return None
        scores.append(math.ceil(sum(items) / cap) / len(bins))
    return sum(scores) / len(scores)

try:
    quick = run_stage(seed=1, n_inst=2, n_items=10)          # stage 1: tiny and fast
    full = run_stage(seed=2, n_inst=20, n_items=60) if quick is not None else None   # stage 2: the real test
    print("RESULT " + json.dumps({{"score": full or 0.0, "valid": full is not None,
                                  "stage": 2 if quick is not None else 1}}))
except Exception as e:
    print("RESULT " + json.dumps({{"score": 0.0, "valid": False, "error": repr(e)[:200]}}))
'''

def evaluate_packer(code):
    r = run_sandboxed(BP_HARNESS.format(code=code), timeout=10)
    if not r["ok"]:
        return 0.0, r["error"][-200:]
    res = r["result"]
    return float(res.get("score", 0.0)), res.get("error") or ("ok" if res.get("valid") else f"invalid at stage {res.get('stage')}")

seed_score, note = evaluate_packer(SEED_PROGRAM)
print(f"seed program (next fit): score {seed_score:.3f} ({note})")

The mutation step. We ask for the whole function back. (AlphaEvolve asks for diffs in a SEARCH/REPLACE format and marks the parts that may change with # EVOLVE-BLOCK-START / # EVOLVE-BLOCK-END. Whole functions are easier for an 8B model.)

a06_open_ended_evolution.ipynb · cell 5
def mutate(parent, inspirations):
    insp = "\n\n".join(f"# score {p['score']:.3f}\n{p['code']}" for p in inspirations)
    prompt = textwrap.dedent(f"""\
        You are improving a Python function for bin packing. Higher score is better (1.0 is a perfect packing).
        A packing that loses, duplicates or overfills items scores 0.

        Current program (score {parent['score']:.3f}):
        ```python
        {{parent}}
        ```

        Other programs from the archive, for inspiration:
        {{insp}}

        Write an improved version of `pack(items, capacity)`. It must return a list of bins, each a list of the
        item sizes in it, using every item exactly once. Use only the Python standard library. It must run in
        well under a second for 60 items. Think about which known heuristics pack tighter.
        Reply with one ```python code block containing the full function.""").replace("{parent}", parent["code"]).replace("{insp}", insp or "(none yet)")
    try:
        return code_block(ask(prompt, temperature=0.8, max_tokens=900))
    except Exception as e:
        return f"# model error: {e}"

archive = [{"code": SEED_PROGRAM, "score": seed_score, "gen": 0, "note": note}]
rng = random.Random(0)
GENERATIONS, CHILDREN = (10, 2) if RUN_LONG else (6, 2)           # 12 model calls by default
best_by_gen = [seed_score]
t0 = time.time()
for gen in range(1, GENERATIONS + 1):
    ranked = sorted(archive, key=lambda p: -p["score"])
    parents = [ranked[0] if rng.random() < 0.5 else rng.choice(ranked[:4]) for _ in range(CHILDREN)]
    with ThreadPoolExecutor(2) as ex:
        kids = list(ex.map(lambda par: mutate(par, [p for p in ranked[:3] if p is not par][:2]), parents))
    for code in kids:
        if "def pack(" not in code:
            archive.append({"code": code, "score": 0.0, "gen": gen, "note": "no pack() function"})
            continue
        s, note = evaluate_packer(code)
        archive.append({"code": code, "score": s, "gen": gen, "note": note})
    best_by_gen.append(max(p["score"] for p in archive))
    print(f"gen {gen}: children scored {[round(a['score'], 3) for a in archive[-CHILDREN:]]}  best so far {best_by_gen[-1]:.3f}")
print(f"[{time.time() - t0:.0f}s]")

best_prog = max(archive, key=lambda p: p["score"])
print(f"\nseed {seed_score:.3f} -> best {best_prog['score']:.3f} (found in generation {best_prog['gen']})\n")
print(best_prog["code"])

Things to notice: - The archive only gets better or stays the same, because we never throw away the best program. Children that crash or cheat get a 0 and are simply never picked as parents. - The evaluator does the real work. The LLM is just a source of guesses. AlphaEvolve's results came from problems where a program can score the answer. A typical win here is "first fit decreasing": sort items from big to small, put each one in the first bin where it fits.

3. Mini ADAS: a meta-agent that invents agent designs

ADAS (Hu, Lu & Clune 2024, Automated Design of Agentic Systems) writes agents as code: a forward() function that may call the model several times. A meta agent reads an archive of earlier designs with their scores and writes a new one. In the paper (GPT-4 as meta agent, GPT-3.5 running the agents), discovered agents beat hand-designed ones by 13.6 F1 points on DROP and 14.4% on MGSM, and kept an edge when moved to other domains and models.

The course page links this lecture item to arXiv 2505.22954, which is the follow-up paper, the Darwin Gödel Machine (Zhang et al. 2025). It applies the same archive idea to a coding agent that edits its own code: SWE-bench 20.0% -> 50.0%.

Our version: agents are forward(question, ask) functions. ask(prompt, temperature=0.0) calls the small 3B model, at most 2 calls per question. The tasks are seeded word problems with exact answers. Each design runs in the sandbox.

a06_open_ended_evolution.ipynb · cell 6
def word_problems(n, seed):
    rng, out = random.Random(seed), []
    for _ in range(n):
        a, b, c, d = rng.randint(20, 90), rng.randint(3, 9), rng.randint(4, 12), rng.randint(5, 30)
        name, thing = rng.choice(["Mia", "Ravi", "Ana", "Tom", "Lena"]), rng.choice(["stickers", "apples", "cards", "coins"])
        kind = rng.randint(0, 2)
        if kind == 0:
            q, ans = f"{name} has {a} {thing}. {name} buys {b} packs with {c} {thing} each, then gives away {d}. How many {thing} does {name} have now?", a + b * c - d
        elif kind == 1:
            q, ans = f"A box holds {c} {thing}. {name} fills {b} boxes and has {d} {thing} left over, then loses {a % 10} of the left-over ones. How many {thing} did {name} have in total at the end?", b * c + d - a % 10
        else:
            q, ans = f"{name} had {a} {thing}, sold {d} of them, and then doubled what was left. After that {name} received {b * c} more. How many {thing} now?", 2 * (a - d) + b * c
        out.append({"question": q, "answer": ans})
    return out

def extract_int(text):
    m = re.findall(r"Answer:\s*\**\s*(-?\d[\d,]*)", text or "", re.I) or re.findall(r"-?\d[\d,]*", text or "")
    try:
        return int(m[-1].replace(",", "")) if m else None
    except ValueError:
        return None

AGENT_HARNESS = '''
import json, sys
sys.path.insert(0, {repo!r})
from lal.llm import ask as _ask
LIMIT, CALLS = 2, {{"n": 0}}

def ask(prompt, temperature=0.0):
    if CALLS["n"] >= LIMIT:
        raise RuntimeError("call budget exceeded")
    CALLS["n"] += 1
    return _ask(str(prompt), model_name={worker!r}, temperature=float(temperature), max_tokens=300)

{code}

outs = []
for q in {questions!r}:
    CALLS["n"] = 0
    try:
        outs.append(str(forward(q, ask)))
    except Exception as e:
        outs.append("ERROR: " + repr(e)[:200])
print("RESULT " + json.dumps(outs))
'''

def evaluate_agent(code, tasks):
    prog = AGENT_HARNESS.format(repo=REPO, worker=WORKER, code=code, questions=[t["question"] for t in tasks])
    r = run_sandboxed(prog, timeout=240, mem_mb=None)        # no memory cap: the model client needs room
    if not r["ok"]:
        return 0.0, "crashed: " + r["error"][-200:]
    outs = r["result"]
    right = sum(extract_int(o) == t["answer"] for o, t in zip(outs, tasks))
    errors = sum(o.startswith("ERROR") for o in outs)
    return right / len(tasks), f"{errors}/{len(tasks)} questions errored"

SEEDS = [
    {"name": "Direct", "idea": "Ask for the number only.",
     "code": "def forward(question, ask):\n    return ask(question + '\\nReply with only the final number.')\n"},
    {"name": "Chain of thought", "idea": "Reason step by step, then give the answer.",
     "code": "def forward(question, ask):\n    return ask(question + \"\\nThink step by step, then end with 'Answer: <number>'.\")\n"},
]
adas_tasks = word_problems(6, seed=7)
t0 = time.time()
agent_archive = []
for s in SEEDS:                                                  # 2 designs x 6 questions = 12 calls
    acc, note = evaluate_agent(s["code"], adas_tasks)
    agent_archive.append({**s, "score": acc, "note": note, "gen": 0})
    print(f"seed {s['name']:<18} accuracy {acc:.0%} ({note})")
print(f"[{time.time() - t0:.0f}s]")

The meta agent. ADAS adds two self-reflection rounds to check that each idea is new, and up to five repair rounds when a design crashes. We skip both to keep the call count small.

def propose_design():
    shown = "\n\n".join(f"Name: {a['name']}\nIdea: {a['idea']}\nAccuracy: {a['score']:.0%}\n```python\n{a['code']}```"
                        for a in sorted(agent_archive, key=lambda a: -a["score"]))
    prompt = textwrap.dedent("""\
        You design agents that solve short math word problems. An agent is a Python function
        `forward(question, ask)` that returns a string containing the final answer. `ask(prompt, temperature=0.0)`
        calls a small language model and returns its text reply. You may call `ask` AT MOST 2 times per question.
        Use only plain Python (re is allowed via `import re` inside the function).

        Archive of designs tried so far, best first:
        {shown}

        Propose a NEW design that is meaningfully different from the archive and likely to score higher
        (ideas: plan then compute, write the arithmetic as one expression and check it, verify and fix, ...).
        Reply in exactly this format:

        Idea: <one sentence>

            ...

    try:

    return {"name": name, "idea": idea, "code": code_block(reply)}

4. An "AI Scientist" loop in miniature

The AI Scientist (Lu et al. 2024) chains the whole research process: idea -> experiment code -> run -> write-up -> automated review. The authors report under $15 per paper, and an automated reviewer (GPT-4o) with 0.65 balanced accuracy at accept/reject on 500 ICLR 2022 papers, against 0.66 for humans.

Ours runs on bin packing, so it is cheap to test. Five calls at most. We add one check the model cannot fake: do the numbers in the write-up actually appear in the results?

def grounded_fraction(text, res):
    """Share of numbers in the write-up that match a result value (to 2 decimals) or appear in the results text."""
    vals = [v for v in res.values() if isinstance(v, (int, float))] if isinstance(res, dict) else []
    nums = [float(x) for x in re.findall(r"-?\d+\.?\d*", text.replace(",", ""))]
    nums = [n for n in nums if n not in (0, 1, 2)]               # small counts like "two heuristics" are noise
    if not nums:
        return None
    raw = json.dumps(res)
    ok = sum(any(abs(n - v) < 0.005 or abs(n - round(v * 100, 1)) < 0.06 for v in vals) or str(n).rstrip("0").rstrip(".") in raw
             for n in nums)
    return ok / len(nums)

try:
    review = structured(f"You are a strict reviewer. Review this short research note.\nHypothesis: {idea.hypothesis}\n"
                        f"Plan: {idea.plan}\nRaw results: {json.dumps(results)}\nNote:\n{writeup}\n"
                        "Score soundness and clarity 1-5 and overall 1-10. Punish any claim not supported by the raw results.",
                        Review)
except Exception as e:
    review = None
    print("review failed:", e)
g = grounded_fraction(writeup, results)
print(f"\nREVIEW: {review.model_dump() if review else None}")
print(f"numbers in the write-up found in the results: {'n/a' if g is None else f'{g:.0%}'}   [{time.time() - t0:.0f}s]")

What this shows, and what it does not: - Each step is checkable except the idea itself. The experiment either ran or it did not; the numbers are either in the results or they are not. - The LLM reviewer is the weakest link. It is one model grading another, and it can be fooled by confident writing. That is why we added the grounding check, which is plain code. - The real AI Scientist uses much bigger models, a literature search to check novelty, and full LaTeX papers. The loop is the same.

Traps
  • An evaluator without a validity check. The search will find the loophole (in the notebook, one overfilled bin scores 27 out of a 'perfect' 1.0).
  • Trusting a win on a tiny search set. With 6 questions one answer is 17 points; confirm the winner on held-out data.
  • Running model-written code in your own Python process. Always use a subprocess or container with a timeout; the AI Scientist raised its own timeout when it could.
  • Keeping only the current best. Without an archive and some diversity, the search gets stuck on one line of ideas.
  • Letting an LLM reviewer be the only judge. Check numbers and claims against the raw results with code.

Check yourself

Why does AlphaEvolve run an evaluation cascade instead of the full test on every child?

Most children are worse or broken; a tiny fast test filters them out early, so the expensive test is spent only on promising ones.

In ADAS, what does the meta agent output, and how is it judged?

A new agent written as code (a forward() function); it is run on validation tasks and its score is stored with it in the archive.

Name two safety measures for an AI Scientist-style loop.

Run generated code in a sandbox (separate process or container) with time, memory and storage limits and no network; check the write-up's claims against the raw results with code rather than trusting the LLM reviewer.
