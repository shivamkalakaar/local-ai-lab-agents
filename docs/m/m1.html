Part 1History of agents

Agents today

2/48
  • Products called agents: Gemini, Cursor, OpenAI Codex, Claude.
  • They do multi-step work, not one reply. The lecture's example is a "Cowork" task list:
    • read meeting transcripts → pull out key points → find action items → check Google Calendar → build a standup deck
  • Each step reads files or uses an app, then decides the next step.

Before 1990: the word and the first uses

3/48
  • "Agent": from Latin agens, late 15th century, "one who acts."
  • First indexed AI use: Hewitt, Bishop and Steiger, "A Universal Modular ACTOR Formalism," IJCAI 1973.
    • Actor: one kind of object that does everything (no separate data and control structures).
  • Contract Net Protocol (Reid G. Smith, 1980): agents negotiate who does which task.
  • Marvin Minsky, The Society of Mind (1986): a mind built from many small agents.

The 1990s: defining an agent

4/48
Source Definition
Pattie Maes, Designing Autonomous Agents (1994) Edited volume on autonomous agents, from biology to engineering
Wooldridge and Jennings (1995) An agent has autonomy, social ability, reactivity and proactivity
Russell and Norvig, AI textbook (1995) Anything that perceives through sensors and acts through actuators
  • The Russell and Norvig definition is the one still quoted today.

The RL era

5/48
  • Agent–environment loop (Sutton and Barto, 1998):
    • agent sees state S_t and reward R_t → takes action A_t → environment returns S_t+1 and R_t+1
  • RL: reinforcement learning; learn actions by trial and reward.
  • DQN on Atari (Mnih et al., 2015): a neural network reads the game screen and picks a joystick move.
  • AlphaGo (Go) and OpenAI Five vs the Dota 2 team OG: RL agents beat top human players.
  • Limit: each agent learned one game. No language, no general tasks.

The LLM era

6/48
  • Transformer: the network design behind modern LLMs (encoder and decoder blocks with attention).
  • GPT-3 showed in-context learning:
    • Few-shot: the prompt holds a task description plus a few examples. No gradient updates (no retraining).
    • "Translate English to French: sea otter → loutre de mer, peppermint → menthe poivrée ... cheese →"
  • One model, many tasks, steered only by the prompt.

What LLMs made possible: reasoning and tool use

7/48
Idea What it does
Chain of thought (CoT) Model writes steps before the answer. "23 apples − 20 = 3, + 6 = 9. The answer is 9." ✓
WebGPT (OpenAI, Dec 16, 2021) Model browses the web to improve factual accuracy
MRKL (2022) Modular Reasoning, Knowledge and Language: LLM routes the input to experts (weather API, currency, wiki API, calendar, database, calculator), then writes the output
  • Reasoning + tools = the two parts that turned chat models into agents.

Agents: key components

12/48
  • LLM core: reads the situation and decides or writes.
  • Planning & reasoning and memory feed into the LLM core.
  • Tools: retrieval, calculator, code, search, read/write memory, file operations.
  • Agent actions: tool call, interaction, response to users.
  • Environment (external world): desktop OS, web browser, mobile apps, games, databases.
    • The agent observes the environment and acts on it.
Planning & Reasoning + Memory → LLM Core → Tools → Agent actions → act → Environment

Reasoning and planning

14/48
  • For humans: mental processes such as deduction, analogy and planning.
  • For LLMs: intermediate text that imitates some (not all) human mental processes.
    • StrategyQA: "Would a pear sink in water?" → "density about 0.6 g/cm³, less than water, so it floats. No."
    • Date understanding: "concert on 06/01/1943, delayed one day to today; date 10 days ago?" → 05/23/1943.
  • For agents: internal actions that update the agent's own state (no change to the world).

Why reasoning helps agents

15/48
Step Content
Obs t You are cooking a dish and see salt is out
Reasoning "The dish should be savory; salt is out, so find the soy sauce. It is in the cabinet to my right."
Act t Turn right
Obs t+1 You see a cabinet and a table
Act t+1 Open cabinet
  • Mapping an observation straight to an action can be hard.
  • Reason to act gives: 1. generalization (new situations), 2. alignment (actions match the goal).

Reasoning without acting

16/48
  • Question: "Aside from the Apple Remote, what other device can control the program Apple Remote was originally designed to interact with?"
  • Standard (answer only): "iPod" ✗
  • Reason only (CoT): "Apple Remote was designed for Apple TV. Apple TV can be controlled by iPhone, iPad, and iPod Touch." ✗
    • The first fact is made up. Reasoning from memory cannot check it.

Reasoning with acting (ReAct)

17/48
  1. Thought: search Apple Remote. Act: Search[Apple Remote]. Obs: "originally designed to control the Front Row media center program."
  2. Act: Search[Front Row]. Obs: "Could not find [Front Row]. Similar: ... 'Front Row (software)'."
  3. Act: Search[Front Row (software)]. Obs: "a discontinued media center software."
  4. Thought: "controlled by an Apple Remote or the keyboard function keys." Act: Finish[keyboard function keys] ✓
  5. Each thought is checked against what the tool returns, and a failed search leads to a better one.

Where ReAct and CoT fail

19/48
Type Definition ReAct CoT
True positive Correct reasoning trace and facts 94% 86%
False positive Hallucinated trace or facts 6% 14%
Reasoning error Wrong trace, incl. failing to recover from repetitive steps 47% 16%
Search result error Search returned nothing useful 23% –
Hallucination Made-up trace or facts 0% 56%
Label ambiguity Right answer, didn't match label exactly 29% 28%
  • Hallucination: the model states something false as fact. A serious problem for CoT; ReAct helps.
  • ReAct's main failure is looping or wrong steps (47%). That is why our loop has a stuck detector.

Self-consistency (Wang et al., 2023)

20/48
  • Prompt the model with chain of thought.
  • Sample a diverse set of reasoning paths (temperature above 0).
  • Pick the most consistent final answer (majority vote).
Greedy CoT (one path) Self-consistency (three paths)
"3 + 4 = 7 eggs used, sells the rest... $14 per day." ✗ $18, $26, $18 → majority: $18 ✓
  • Example: Janet's ducks lay 16 eggs; she eats 3, bakes with 4, sells the rest at $2.

Reflexion: agents reflect in words (Shinn et al., 2023)

21/48
  • Reflexion agents verbally reflect on task feedback, then keep that reflective text to make better decisions.
  • Parts: Actor (LM) acts; Evaluator (LM) scores the trajectory; Self-reflection (LM) writes a lesson.
  • Memory: trajectory (short-term) and experience (long-term, the lessons).
  • Decision-making example: "tried to pick up the pan in stoveburner 1, but the pan was not in stoveburner 1" → next try: stoveburner 2 ✓
  • Programming example: self-written unit tests fail → "it only checks the total count of parentheses, not the order" → fixed code.

Reflexion results (ALFWorld)

22/48
  • ALFWorld: text-based household tasks.
  • Self-reflection distills long, failed trajectories into "self-hints" for next time.
Trial ReAct only ReAct + Reflexion (heuristic) ReAct + Reflexion (GPT)
0 about 0.63 solved about 0.63 about 0.63
Last shown about 0.75 (trial 7) about 0.97 (trial 10) about 0.94 (trial 10)
  • Hallucination errors: ReAct only stays around 0.21 of environments; with Reflexion it falls from about 0.32 to about 0.03.
  • Inefficient planning with Reflexion drops to 0.

Round Agent 1 Agent 2

  • Task: run a Python script from an image; its output is a URL with C++ code; compile, run, return the sum of the 3rd and 5th integers.

The need for memory

25/48
  • The context window cannot hold every event the agent sees.
  • Even if it could, the model may fail to attend to the relevant events or digest them.
  • Generative agents (Park et al.): perceive → memory stream → retrieve → retrieved memories → act.
    • Plan and reflect both read from and write back to the memory stream.

Types of memory

Episodic memory

27/48
  • Write: append-only event stream with timestamps ("22:48:10 Isabella Rodriguez is stretching", "desk is idle").
  • Read: retrieval by a heuristic score.
    • retrieval = recency + importance + relevance
    • Recency: how recent. Importance: how notable. Relevance: how close to the question.
  • Q: "What are you looking forward to?" Top memory: planning a Valentine's Day party (2.34 = 0.91 + 0.63 + 0.80).
  • Answer: "I'm looking forward to the Valentine's Day party that I'm planning at Hobbs Cafe!"

Semantic memory

28/48
  • Write: the LLM reasons over many events and writes a reflection.
  • Read: retrieval.
  • Example tree (Klaus Mueller):
    • Observations: "reading and taking notes on the articles", "engaging with a librarian"
    • Reflections: "dedicated to research", "spends many hours reading"
    • Top reflection: "Klaus Mueller is highly dedicated to research"
  • Knowledge is built from experience, not stored raw.

Procedural memory: Voyager (Wang et al., 2023)

29/48
  • Minecraft agent that learns skills as code.
  • Automatic curriculum: proposes the next task (mine wood log → make crafting table → combat zombie → mine diamond).
  • Iterative prompting: writes code as actions; gets environment feedback and execution errors; refines.
  • Self-verification: if the task worked, add the code to the skill library.
  • Write: code-based skills. Read: embedding retrieval (find skills by meaning, e.g., craftStoneSword, craftShield).

Toolformer: LLMs teach themselves to use tools

30/48
  • Toolformer (Schick et al., 2023) trains a model to decide which APIs to call, when, with what arguments, and how to use the results.
  • Tools: calculator, Q&A system, search engine, translation, calendar.
  • Calls appear inline in text:
    • "Out of 1400 participants, 400 (or [Calculator(400 / 1400) → 0.29] 29%) passed the test."
    • "[MT("tortuga") → turtle]", "[WikiSearch("Brown Act") → ...]"

Gorilla: LLMs connected to massive APIs (Patil et al., 2023)

31/48
  • Data: 1,645 API calls (94 Torch Hub, 626 TensorFlow Hub v2, 925 HuggingFace top 20 per domain).
  • Self-instruct with examples → 16,450 (instruction, API) pairs → train Gorilla-7B.
  • With a retriever: the API docs are fetched and added to the prompt.
0-shot (no retriever) With BM25 retriever
Gorilla about 70% accuracy, lowest hallucination GPT-3.5, GPT-4, Claude, Gorilla cluster near 30–37% accuracy
GPT-3.5, GPT-4, Claude lower; Claude hallucinates most; LLaMA near 0 LLaMA stays low, with high hallucination
  • BM25: keyword search. A fine-tuned small model beat large general models at picking the right API.

Putting it all together: skeleton of an agent

32/48
  • Planning & reasoning: ReAct, self-consistency, Reflexion, debate, orchestrator.
  • Memory: episodic, semantic, procedural.
  • Tools: Toolformer, Gorilla, function calling.
  • Environment: what the agent observes and acts on.
  • LLM core in the middle.

The agent loop

34/48
  1. Send the task plus a list of tools with short descriptions.
  2. Model replies: a tool call, or a final answer.
  3. Tool call → your code runs it, adds the result to the messages.
  4. Repeat until an answer or a safety limit.
task → LLM → tool call → run tool → result → LLM → ... → answer

Four safety limits

35/48
  • Turn cap: stop after max_turns rounds. Loops are the most common agent failure (ReAct: 47% of failures were reasoning errors, including repeated steps).
  • Stuck detector: same tool call twice → "you already made this exact call."
  • Errors as results: a failed tool sends its error back, so the model can fix its call.
  • Format check: small models sometimes write a tool call as text. Send back "FORMAT ERROR."

The loop in code

36/48
for turn in range(max_turns):                                   # limit 1: turn cap
    msg = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS, temperature=0).choices[0].message
    messages.append(msg)
    if not msg.tool_calls:
        return {"answer": msg.content, "turns": turn + 1, "tool_calls": calls}
    for call in msg.tool_calls:
        ...
        messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)})
  • Line 1: the loop runs at most max_turns times.
  • Line 2: send all messages plus the tool list; get the reply.
  • Line 3: keep the reply, so the model sees it next turn (memory).
  • Lines 4–5: no tool call → the model is done. Return its answer.
  • Lines 6–8: run each tool call (with the limits) and add the result (observation).
Part 3Compound AI systems: RAG, tool use, MCP

Agents: three layers

37/48
  • Despite many components, agent engineering splits into three layers:
    • The system: architecture design (which parts, how they connect).
    • The data: training examples, demonstrations, context.
    • The evals: test cases plus the metric.
  • Our course: the system is the loop or workflow; the data is the 20 practice contracts; the evals are their known answers.

Workflows vs agents: who decides the steps?

38/48
  • Both are compound AI systems: an LLM plus other components (Zaharia et al., BAIR, 2024).
  • Workflow: code fixes the steps (e.g., Agentless, AlphaCode 2).
  • Agent: the LLM decides the steps (e.g., SWE-agent).
  • AlphaCode 2: fine-tuned LLMs sample and score programs, plus a code-execution module. Generates up to 1 million solutions per problem, then filters and scores them.
    • Ranked at the 87th percentile of human contestants, vs about the 46th for the original AlphaCode (estimated).

Retrieval-augmented generation (RAG)

41/48
  • RAG connects an LLM to outside knowledge at answer time.
  • Retrieve: search your documents for relevant text.
  • Augment: add that text to the user's question.
  • Generate: the LLM answers using the retrieved facts.
  • Example: "What protects the digestive system against infection?" → retriever finds a Wikipedia passage → reader answers "gastric acid and proteases [1]", with its source.
  • Full pipeline: Module 4.

Part 4How this applies to us

Workflow first for contract review

44/48
  • Checking a contract against a playbook has known steps: find the clause, read the cap, compare to 12 months. That is a workflow.
  • Keep agents for tasks where the next step depends on what you find ("research this counterparty").
  • Same three layers: system (workflow), data (practice contracts), evals (known answers).

Small local models need a tight harness

45/48
  • Local models are small. Every choice handed to them is a chance to fail.
  • ReAct's top failure was looping (47%). Turn caps and stuck detectors matter more for an 8B model.
  • Tools should return clear errors ("NOT FOUND. Valid clauses: ...") so the model can recover.

Part 5Wrap-up

Common mistakes

47/48
  • Agent because it sounds impressive → if you know the steps, write a workflow.
  • No turn limit → a confused agent rereads the same clauses forever.
  • Crashing on tool errors → return "NOT FOUND. Valid clauses: ..." so it can recover.
  • Reasoning only, no tools → made-up facts (56% of CoT failures). Make the model read the source.
  • Accuracy without cost → retries buy accuracy. Show time and cost too.

Check your understanding

A firm wants every NDA checked against its 12-point playbook. Agent or workflow?

Workflow. The steps are known and the same every time; use the model to read clauses and do the checks in code.

What are the five parts of an agent, and which one is the `messages` list in our loop?

LLM core, planning & reasoning, memory, tools, environment. The growing `messages` list is the memory: the traces so far.

Why did ReAct have 0% hallucination failures while CoT had 56%?

ReAct checks each step against what a search tool returns. CoT reasons only from what the model remembers, so it can't catch a false fact.

What does self-consistency do?

It samples several chain-of-thought answers and picks the one that appears most often.

Name the three memory types by content and an example of each.

Episodic stores experience and semantic stores knowledge (both in generative agents); procedural stores skills (Voyager's code skill library).

What does the stuck detector do?

It spots the exact same tool call made twice and, instead of running it, tells the model to use what it has or answer.

What problem does MCP solve?

One standard protocol between AI apps and tools, so a tool written once as an MCP server works with any MCP app.

Go deeper

Key terms, papers, evidence, the full notebook code and worked solutions.

Lecture 1 · Zaharia et al., "Compound AI Systems" · Weng, "LLM Powered Autonomous Agents" · Kapoor et al., "AI Agents That Matter"

An agent is an LLM in a loop that picks its own next step, uses tools, and sees the results. Most real business tasks should not be agents. They should be workflows, where your code fixes the steps and the LLM fills in the fuzzy parts.

Key terms

Agent
An LLM running in a loop that chooses its own next action, calls tools, observes the results, and stops when it decides the task is done.Source: Weng, "LLM Powered Autonomous Agents" (2023); CS329Z Lecture 1
Compound AI system
A system that gets its results from several interacting parts (model calls, retrievers, tools, code) rather than one model call. Most production AI is built this way.Source: Zaharia et al., "The Shift from Models to Compound AI Systems", BAIR (2024)
Workflow
A compound system whose steps are fixed in code. The LLM fills in fuzzy parts but does not decide what happens next.Source: Schluntz & Zhang, "Building Effective Agents", Anthropic (2024)
ReAct
Reason + Act: the model alternates a short thought, an action (tool call) and an observation. Grounding reasoning in actions cut made-up facts compared with reasoning alone.Source: Yao et al., "ReAct", ICLR (2023)
Cost-controlled evaluation
Reporting accuracy together with cost, because retries can buy accuracy. Simple baselines (retry, escalate to a stronger model) often match complex agents.Source: Kapoor et al., "AI Agents That Matter", TMLR (2025)

The anatomy

  • LLM core: reads the situation and decides or writes.
  • Reasoning: thinking before acting (chain of thought, planning).
  • Tools: functions it can call, such as search, a database, or code.
  • Memory: what it keeps between steps and between sessions.
  • Environment: the world it acts on, which sends back results.

from lal.llm import client, ask
from lal.data import contract, clauses, sections, labels

def list_sections(contract_id: str) -> str:
    """Section headings with numbers."""
    return "\n".join(f"{s['id']}. {s['title']}" for s in sections(contract(contract_id)))

def get_clause(contract_id: str, clause: str) -> str:
    """One numbered clause, e.g. '7.1'."""
    cl = clauses(contract(contract_id))
    return cl.get(clause, f"NOT FOUND. Valid clauses: {', '.join(cl)}")

TOOLS = [
    {"type": "function", "function": {"name": "list_sections",
        "description": "List the section headings of a contract with their numbers. Call this first.",
        "parameters": {"type": "object", "properties": {"contract_id": {"type": "string"}}, "required": ["contract_id"]}}},
    {"type": "function", "function": {"name": "get_clause",
        "description": "Read one clause by number, for example '7.1' or '10.1'.",
        "parameters": {"type": "object", "properties": {"contract_id": {"type": "string"}, "clause": {"type": "string"}},
                       "required": ["contract_id", "clause"]}}},
]
IMPL = {"get_clause": get_clause, "list_sections": list_sections}

2. The agent loop

Four safety limits matter most: a turn cap, a stuck detector (the same call twice), errors returned as results so the model can fix its own mistakes, and a format check: small local models sometimes write a tool call as text instead of making it, so we send that back as an error.

01_agent_loop.ipynb · cell 3
def run_agent(task, max_turns=8, verbose=True):
    messages = [{"role": "system", "content": "You review contracts. Use the tools to read clauses before answering. Cite clause numbers."},
                {"role": "user", "content": task}]
    seen, calls = set(), 0
    for turn in range(max_turns):                                   # limit 1: turn cap
        msg = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS, temperature=0).choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            if '"name"' in (msg.content or "") and turn < max_turns - 1:     # limit 4: a tool call written as text
                messages.append({"role": "user", "content": "FORMAT ERROR: you wrote a tool call as text. "
                                 "Use the tool-calling interface, or give your final answer in plain words."})
                continue
            return {"answer": msg.content, "turns": turn + 1, "tool_calls": calls}
        for call in msg.tool_calls:
            calls += 1
            key = (call.function.name, call.function.arguments)
            if key in seen:                                         # limit 2: stuck detector
                result = "ERROR: you already made this exact call. Use the result you have, or answer."
            else:
                seen.add(key)
                try:
                    result = IMPL[call.function.name](**json.loads(call.function.arguments))
                except Exception as e:                              # limit 3: errors become results
                    result = f"ERROR: {type(e).__name__}: {e}. Check the tool name and arguments."
            if verbose:
                print(f"  turn {turn+1}: {call.function.name}({call.function.arguments}) -> {str(result)[:90]}")
            messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)})
    return {"answer": "STOPPED: turn limit reached.", "turns": max_turns, "tool_calls": calls}

t0 = time.time()
out = run_agent("In contract msa_07, what is the liability cap? Quote the clause.")
print("\nANSWER:", out["answer"])
print(f"{out['turns']} turns, {out['tool_calls']} tool calls, {time.time()-t0:.1f}s")

3. The same task as a workflow

We already know where the liability clause is, so code fetches it and the model only reads one clause. Fewer decisions for the model means fewer ways to fail.

def cap_workflow(cid):
    sec = next(s for s in sections(contract(cid)) if "Liability" in s["title"])     # code finds the clause
    return ask(f"{sec['text']}\n\nWhat is the liability cap, in months of fees? "
               f"Answer with just a number, or 'none' if liability is unlimited.")   # model reads it

t0 = time.time()
print(cap_workflow("msa_07"), f"({time.time()-t0:.1f}s)")
print("Truth:", labels()["msa_07"]["terms"]["liability_cap_months"])

def to_months(text):
    if not text: return "?"
    if re.search(r"\b(none|unlimited|no cap|not limited)\b", text.lower()): return None
    for word, n in {"twelve": 12, "twenty-four": 24, "thirty-six": 36}.items():
        if word in text.lower(): return n
    m = re.search(r"\b(12|24|36)\b", text)
    return int(m.group(1)) if m else "?"

rows = []
for cid in ["msa_01", "msa_07", "msa_08", "msa_15", "msa_18"]:
    truth = labels()[cid]["terms"]["liability_cap_months"]
    t0 = time.time(); a = run_agent(f"In contract {cid}, what is the liability cap in months of fees? Answer with a number or 'none'.", verbose=False); ta = time.time()-t0
    t0 = time.time(); w = cap_workflow(cid); tw = time.time()-t0
    rows.append((cid, truth, to_months(a["answer"]) == truth, round(ta, 1), to_months(w) == truth, round(tw, 1)))
print(f"{'contract':9} {'truth':>5} {'agent ok':>9} {'secs':>5} {'workflow ok':>12} {'secs':>5}")
for r in rows:
    print(f"{r[0]:9} {str(r[1]):>5} {str(r[2]):>9} {r[3]:>5} {str(r[4]):>12} {r[5]:>5}")

# Solution 2: add a search_text tool
STOP = {"of", "the", "a", "an", "to", "in", "for", "and", "or", "is", "how", "many", "what"}
def search_text(contract_id: str, phrase: str) -> str:
    """Return every clause containing ALL the meaningful words of the phrase ("days of notice" finds "days' prior written notice")."""
    words = [w for w in re.findall(r"[a-z0-9]+", phrase.lower()) if w not in STOP]
    hits = [f"{num}: {text}" for num, text in clauses(contract(contract_id)).items() if all(w in text.lower() for w in words)]
    return "\n".join(hits) or "No clause contains those words. Try one keyword."

TOOLS.append({"type": "function", "function": {"name": "search_text",
    "description": "Find clauses in one contract that contain all the given keywords, e.g. 'notice renewal' or 'governing law'. Faster than reading every clause.",
    "parameters": {"type": "object", "properties": {"contract_id": {"type": "string"}, "phrase": {"type": "string"}},
                   "required": ["contract_id", "phrase"]}}})
IMPL["search_text"] = search_text

out = run_agent("In contract msa_13, how many days of notice are needed to stop the renewal?")
print("\nANSWER:", out["answer"], "| truth:", labels()["msa_13"]["terms"]["notice_days"])
Traps
  • Building an agent because it sounds impressive when a workflow would do.
  • Reporting accuracy without cost. Retries can buy accuracy, so always show both.
  • No turn limit. Loops are the most common agent failure (47% of ReAct's failures involved repeated or wrong reasoning steps).

Check yourself

A law firm wants every NDA checked against its 12-point playbook. Agent or workflow?

Workflow. The steps are known and the same every time. Use the LLM only to read clauses and spot unusual wording, and do the 12 checks in code wherever possible.

What should you try before building a complex agent?

Simple baselines: retrying, and running a cheap model first and escalating to a stronger one only when a check fails. They often match complex agents at a fraction of the cost.

Try it

Take one task from the Release Desk or the contract-review pilot. Write it as a list of steps, then mark each step C (code can do it) or L (needs an LLM). Most teams find 60–80% of steps are C.
