How to run an AI model on your own computer, send it your first question, and meet the practice contracts we use all course.

The big idea

Most people use AI through a website or a paid service. Your words travel to someone else's computer, get answered there, and come back. This course does it differently. The model lives on the same machine as your files.

Think of it like the difference between sending documents to an outside copy shop and owning a printer. The outside shop is easy. But your papers leave the building. With your own printer, nothing leaves, and there is no charge per page.

A model (the trained AI program that reads text and writes text) is just a large file. A small program called Ollama loads that file and lets your code talk to it. We use Meta's Llama 3.1 8B. The "8B" means 8 billion internal settings. It is about 5 GB to download.

Once it is running, your code asks it questions the same way it would ask a cloud service. Only the address changes.

Why it matters for us

A law firm holds private client contracts. Many firms cannot send those to an outside AI company. Running the model on the firm's own computers solves that. No data leaves the box, and there are no API keys (passwords for paid AI services) to manage.

It also changes the cost picture. On your own hardware there is no bill per word. But speed still matters, because a lawyer will not wait forever. So from day one we measure how fast the model answers.

Finally, we need practice data where we know the right answers. Otherwise we can never tell if our AI is any good.

How it works, step by step

  1. Get a GPU. A GPU (graphics chip) does the heavy math fast. In Colab, Google's free notebook service, you pick "T4 GPU" in the runtime menu.

  2. Run the setup cell. It installs Ollama, starts it, and downloads the model. The first time takes 2 to 3 minutes. Loading the model into the GPU's memory takes about a minute more.

  3. Point your code at localhost. Ollama serves the model at http://localhost:11434. "Localhost" means "this same computer." Ollama speaks the same language as OpenAI's service, so we can use the normal openai Python library.

  4. Send a message, get a reply. You send a list of messages. Each has a role (who is speaking, like "user") and content (the words). The model sends back text.

  5. Measure tokens and speed. A token is a chunk of text, roughly a short word or part of a word. The reply tells you how many tokens you sent and how many came back. Divide output tokens by seconds to get speed.

  6. Pick a temperature. Temperature controls randomness. At 0, the model gives the same answer every time. At higher values, answers vary. Use 0 for anything you will check.

Worked example

Here is the first real call in the notebook.

local = OpenAI(base_url="http://localhost:11434/v1", api_key="not-needed")
resp = local.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "In one sentence: why would a law firm want AI that runs on its own computers?"}],
    temperature=0,
)
reply = resp.choices[0].message.content

Line by line:

  • The first line makes a client (a connection object). base_url points at this machine, not at OpenAI. The key is a dummy value, because nothing leaves the computer.
  • create(...) sends the request. model=MODEL names the model the setup cell downloaded.
  • messages holds one user message: our question.
  • temperature=0 asks for the steadiest answer.
  • The last line pulls the reply text out of the response.

Next, the notebook loads the practice data. There are 20 made-up service agreements. Some have problems planted on purpose:

  • a liability cap that is missing or too large (the firm's playbook says at most 12 months of fees),
  • the wrong governing law (which state's law applies),
  • a long auto-renewal,
  • a short notice period to cancel.

Because we planted the problems, we know the true answer for each contract. For msa_07, the notebook prints the contract text, then the true answer, then the playbook rules. Every later module grades its agents against these answers.

Two small helpers keep later code short. ask(prompt) sends a question and returns text. structured(prompt, Schema) returns data in a fixed shape. Both talk to the same local address.

Common mistakes

  • Forgetting the GPU. Without it, the model runs very slowly. Change the runtime type before you run setup.
  • Judging speed on the first call. The first call includes loading the model into memory. Time the second call instead.
  • Using high temperature for facts. At high temperature, details like the cap period can drift. Use 0 when you extract or check.
  • Testing without known answers. If you don't know the right answer, you can't tell if the AI got it right. Start with labeled data, like our 20 contracts.

Check your understanding

What changes in the code when you switch from a cloud AI service to a local model?

Mainly the address. `base_url` points at localhost, and the API key becomes a dummy value. The rest of the code stays the same.

If there is no bill per token on your own machine, why measure tokens at all?

Speed. More tokens take more time, and lawyers need answers quickly. Token counts also tell you how full the model's input is getting.

Why did we plant problems in the practice contracts?

So we know the right answers. Then we can grade any agent we build and see if a change made it better or worse.

The helper every notebook uses: lal/llm.py

A thin wrapper around the OpenAI-compatible API that Ollama and vLLM expose. Point LAL_BASE_URL somewhere else and the same notebooks run on another server.

lal/llm.py
"""One small wrapper around the OpenAI-compatible API that Ollama (and vLLM) expose.

Change LAL_BASE_URL to point the same code at vLLM or any other server.
"""
import json
import os
import time

from openai import OpenAI

client = OpenAI(base_url=os.getenv("LAL_BASE_URL", "http://localhost:11434/v1"),
                api_key=os.getenv("LAL_API_KEY", "local"))


def model() -> str:
    return os.getenv("LAL_MODEL", "llama3.1:8b")


def chat(messages, model_name=None, **kw):
    """One model call. Returns the assistant message object."""
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    kw.setdefault("temperature", 0)
    resp = client.chat.completions.create(model=model_name or model(), messages=messages, **kw)
    return resp.choices[0].message


def ask(prompt, system=None, **kw) -> str:
    """Shortcut: prompt in, text out."""
    msgs = ([{"role": "system", "content": system}] if system else []) + [{"role": "user", "content": prompt}]
    return chat(msgs, **kw).content or ""


def structured(messages, schema_model, model_name=None, retries=2, **kw):
    """Force the reply to match a Pydantic model (the server enforces the JSON schema), then validate.

    Small models occasionally return a cut-off or empty reply, so we retry a couple of times
    before giving up, and cap the length so a runaway reply can't hang the loop.
    """
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    kw.setdefault("temperature", 0)
    kw.setdefault("max_tokens", 1024)
    fmt = {"type": "json_schema", "json_schema": {"name": schema_model.__name__, "schema": schema_model.model_json_schema()}}
    last = None
    for _ in range(retries + 1):
        resp = client.chat.completions.create(model=model_name or model(), messages=messages, response_format=fmt, **kw)
        try:
            return schema_model.model_validate_json(resp.choices[0].message.content or "")
        except Exception as e:      # invalid or empty JSON: try again
            last = e
    raise last


def timed(fn, *a, **kw):
    """Run fn and print how long it took."""
    t0 = time.time()
    out = fn(*a, **kw)
    print(f"[{time.time() - t0:.1f}s]")
    return out

The code, cell by cell

Everything below is exactly what runs in 00_setup_first_call.ipynb, in the same order. The notebook starts with the shared setup cell (shown in Module 00), then these cells.

1. Talk to the model on this machine

Ollama runs the model on this computer and serves it at http://localhost:11434. It speaks the same API as OpenAI, so we use the normal openai Python library and only change two things: - base_url points at localhost, not at OpenAI's servers; - the API key is a dummy value, because nothing leaves this machine.

The setup cell already loaded the model into GPU memory (that first load takes about a minute), so this call should take a second or two.

00_setup_first_call.ipynb · cell 2
import time
from openai import OpenAI

local = OpenAI(base_url="http://localhost:11434/v1", api_key="not-needed")   # the model server on THIS machine
t0 = time.time()
resp = local.chat.completions.create(
    model=MODEL,                                           # llama3.1:8b, downloaded by the setup cell
    messages=[{"role": "user", "content": "In one sentence: why would a law firm want AI that runs on its own computers?"}],
    temperature=0,
)
reply = resp.choices[0].message.content
print(reply)
print(f"\n{time.time() - t0:.1f} seconds, model = {MODEL}, server = {local.base_url}")

2. Measure speed and token use

On your own hardware there is no per-token bill, but speed still matters.

00_setup_first_call.ipynb · cell 4
t0 = time.time()
resp = local.chat.completions.create(model=MODEL, temperature=0,
    messages=[{"role": "user", "content": "List five common clauses in a services contract, one line each."}])
secs = time.time() - t0
u = resp.usage
print(resp.choices[0].message.content)
print(f"\nprompt tokens: {u.prompt_tokens}, output tokens: {u.completion_tokens}, "
      f"speed: {u.completion_tokens / secs:.0f} tokens/second")

3. Temperature: same question, different settings

Low temperature gives the same answer every time (good for extraction). Higher temperature gives variety (good for brainstorming, or for sampling several candidates to check).

00_setup_first_call.ipynb · cell 5
for temp in (0, 1.0):
    answers = {ask("Name one risky clause in a vendor contract. Answer in 3 words or fewer.", temperature=temp).strip()
               for _ in range(3)}
    print(f"temperature {temp}: {answers}")
