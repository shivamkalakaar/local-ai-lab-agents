What you should already know

4/21
  • Basic LLM ideas: train/dev/test sets, pretraining, fine-tuning, alignment, prompting.
    • Pretraining: learning from a huge pile of text. Fine-tuning: more training on a small, focused set.
  • The lecture recommends CS 224N, 224V, CS 336 or similar; it does not reteach these.
  • Here, Module 2 gives the builder's version of what you need.

The hidden cost: skills erode

5/21
  • RCT (randomized controlled trial): 52 engineers learned a new Python library, with or without AI help (Shen and Tamkin, Anthropic, 2026).
  • AI users scored 17% lower on a follow-up quiz, about two letter grades.
    • Chart: quiz score about 50% with AI vs about 65% without (p = 0.010, a real difference).
    • Task time: about 23 vs about 25 minutes (p = 0.391, no real difference).
  • The gap was largest on debugging, the skill senior engineers are made of.

Homework up, exams down

6/21
Homework score Exam score
Pupils using AI scored higher than before Pupils using AI did worse than before
Distribution shifts right, peak above the no-AI average Distribution spreads left, long tail of low scores
  • Strömberg et al., "The generative AI learning penalty" (preprint, June 2026): 26,811 pupils aged 12–18.
  • Scores set so the average without AI = 100.

Part 2Run a model on your machine

Cloud model vs local model

8/21
Cloud AI service Local model (this course)
Your text goes to someone else's computer The model runs on the same machine as your files
Needs an API key (password for a paid service) No key: api_key="not-needed"
Bill per token No bill per token; speed still matters
  • Same code for both. Only the address changes.

What you need

9/21
  • Ollama: small program that loads a model and serves it on this machine.
  • Model: Meta's Llama 3.1 8B. "8B" = 8 billion parameters. About 5 GB.
  • GPU: graphics chip that does the math fast. In Colab: Runtime → Change runtime type → T4 GPU.
  • Setup cell: installs Ollama, starts it, downloads the model. 2–3 minutes the first time.

Where the model lives

10/21
  • Ollama serves the model at http://localhost:11434.
    • localhost: "this same computer"
  • It speaks the same API as OpenAI, so we use the normal openai Python library.
your code → Ollama on localhost:11434 → Llama 3.1 8B → reply

11/21
Agent part (Lecture 1) Where it comes in

Your first call

12/21
local = OpenAI(base_url="http://localhost:11434/v1", api_key="not-needed")
resp = local.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "In one sentence: why would a law firm want AI that runs on its own computers?"}],
    temperature=0,
)
reply = resp.choices[0].message.content
  • Line 1: client pointed at localhost, not OpenAI. Dummy key.
  • Line 3: MODEL = llama3.1:8b, downloaded by the setup cell.
  • Line 4: one message. Role: who speaks. Content: the words.
  • Line 5: temperature 0, the steadiest answer.
  • Line 7: pull the reply text out.

Measure tokens and speed

13/21
  • Token: a short word or piece of a word. Models read and write tokens.
  • The reply reports prompt_tokens (sent) and completion_tokens (returned).
  • Speed: output tokens ÷ seconds = tokens per second.
  • First model load into GPU memory takes about a minute. Time a later call.

Temperature: same question, different settings

14/21
Temperature 0 Temperature 1.0
Same answer every run Answers vary run to run
Use for extraction and anything you will check Use for brainstorming, or sampling several answers to check
  • Temperature: scales the model's word probabilities. Low = pick the likely word. High = more variety.

Two helpers used in every later notebook

15/21
  • ask(prompt): prompt in, text out.
  • structured(prompt, Schema): forced JSON that matches a Pydantic schema.
  • Both live in lal/llm.py and wrap the same call, at the same localhost address.

Part 4How this applies to us

Nothing leaves the machine

18/21
  • A firm can't send client contracts to an outside AI company. Here the model, the files and the code sit on one box.
  • No API keys to manage, no per-token bill.
  • Same openai code as a cloud service, so nothing about the course depends on a vendor.

Known answers grade every module

19/21
  • Every later module grades its agent against these 20 known answers.
  • A change (new prompt, new model, new tool) counts only if the score goes up.
  • Lecture 1's three layers: system, data, evals. This module gives you the data and the evals.

Speed is the local budget

20/21
  • No bill, but every token costs seconds on your own GPU.
  • Measure tokens per second once now; use it to judge later designs (an agent loop makes many calls, a workflow few).
  • Small 8B model + careful harness is the course's bet; the next modules show how.
Part 5Wrap-up

Common mistakes

21/21
  • No GPU selected → very slow. Change the runtime type before setup.
  • Timing the first call → it includes model loading. Time a later call.
  • High temperature for facts → details like the cap period can drift. Use 0.
  • Testing without known answers → you can't tell if the AI is right. Start with labeled data.

Check your understanding

What changes in the code when you switch from a cloud service to the local model?

The address and the key. `base_url` points at localhost and the key is a dummy value; the rest stays the same.

There is no bill per token on your own machine. Why count tokens at all?

Speed. More tokens take more time, and token counts show how full the model's input is getting.

Why plant problems in the practice contracts?

So we know the right answers. Then we can grade any agent and see if a change helped or hurt.

In the Anthropic study, AI users finished about as fast. What was the cost?

They scored 17% lower on a follow-up quiz, about two letter grades, with the biggest gap on debugging.

Which part of an agent do you set up in this module?

The LLM core: the model on Ollama. Module 1 adds tools, memory and the loop around it.

Why use temperature 0 when summarizing a contract?

The answer stays the same every run, so facts like the cap period don't drift and you can check them.

The helper every notebook uses: lal/llm.py

A thin wrapper around the OpenAI-compatible API that Ollama and vLLM expose. Point LAL_BASE_URL somewhere else and the same notebooks run on another server.

lal/llm.py
"""One small wrapper around the OpenAI-compatible API that Ollama (and vLLM) expose.

Change LAL_BASE_URL to point the same code at vLLM or any other server.
"""
import json
import os
import time

from openai import OpenAI

client = OpenAI(base_url=os.getenv("LAL_BASE_URL", "http://localhost:11434/v1"),
                api_key=os.getenv("LAL_API_KEY", "local"))


def model() -> str:
    return os.getenv("LAL_MODEL", "llama3.1:8b")


def chat(messages, model_name=None, **kw):
    """One model call. Returns the assistant message object."""
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    kw.setdefault("temperature", 0)
    resp = client.chat.completions.create(model=model_name or model(), messages=messages, **kw)
    return resp.choices[0].message


def ask(prompt, system=None, **kw) -> str:
    """Shortcut: prompt in, text out."""
    msgs = ([{"role": "system", "content": system}] if system else []) + [{"role": "user", "content": prompt}]
    return chat(msgs, **kw).content or ""


def structured(messages, schema_model, model_name=None, retries=2, **kw):
    """Force the reply to match a Pydantic model (the server enforces the JSON schema), then validate.

    Small models occasionally return a cut-off or empty reply, so we retry a couple of times
    before giving up, and cap the length so a runaway reply can't hang the loop.
    """
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    kw.setdefault("temperature", 0)
    kw.setdefault("max_tokens", 1024)
    fmt = {"type": "json_schema", "json_schema": {"name": schema_model.__name__, "schema": schema_model.model_json_schema()}}
    last = None
    for _ in range(retries + 1):
        resp = client.chat.completions.create(model=model_name or model(), messages=messages, response_format=fmt, **kw)
        try:
            return schema_model.model_validate_json(resp.choices[0].message.content or "")
        except Exception as e:      # invalid or empty JSON: try again
            last = e
    raise last


def timed(fn, *a, **kw):
    """Run fn and print how long it took."""
    t0 = time.time()
    out = fn(*a, **kw)
    print(f"[{time.time() - t0:.1f}s]")
    return out

The code, cell by cell

Everything below is exactly what runs in 00_setup_first_call.ipynb, in the same order. The notebook starts with the shared setup cell (shown in Module 00), then these cells.

1. Talk to the model on this machine

Ollama runs the model on this computer and serves it at http://localhost:11434. It speaks the same API as OpenAI, so we use the normal openai Python library and only change two things: - base_url points at localhost, not at OpenAI's servers; - the API key is a dummy value, because nothing leaves this machine.

The setup cell already loaded the model into GPU memory (that first load takes about a minute), so this call should take a second or two.

00_setup_first_call.ipynb · cell 2
import time
from openai import OpenAI

local = OpenAI(base_url="http://localhost:11434/v1", api_key="not-needed")   # the model server on THIS machine
t0 = time.time()
resp = local.chat.completions.create(
    model=MODEL,                                           # llama3.1:8b, downloaded by the setup cell
    messages=[{"role": "user", "content": "In one sentence: why would a law firm want AI that runs on its own computers?"}],
    temperature=0,
)
reply = resp.choices[0].message.content
print(reply)
print(f"\n{time.time() - t0:.1f} seconds, model = {MODEL}, server = {local.base_url}")

2. Measure speed and token use

On your own hardware there is no per-token bill, but speed still matters.

00_setup_first_call.ipynb · cell 4
t0 = time.time()
resp = local.chat.completions.create(model=MODEL, temperature=0,
    messages=[{"role": "user", "content": "List five common clauses in a services contract, one line each."}])
secs = time.time() - t0
u = resp.usage
print(resp.choices[0].message.content)
print(f"\nprompt tokens: {u.prompt_tokens}, output tokens: {u.completion_tokens}, "
      f"speed: {u.completion_tokens / secs:.0f} tokens/second")

3. Temperature: same question, different settings

Low temperature gives the same answer every time (good for extraction). Higher temperature gives variety (good for brainstorming, or for sampling several candidates to check).

00_setup_first_call.ipynb · cell 5
for temp in (0, 1.0):
    answers = {ask("Name one risky clause in a vendor contract. Answer in 3 words or fewer.", temperature=temp).strip()
               for _ in range(3)}
    print(f"temperature {temp}: {answers}")
